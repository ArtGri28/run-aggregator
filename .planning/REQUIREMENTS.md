# Requirements: Telegram-бот — агрегатор забегов

**Defined:** 2026-09-25
**Core Value:** Полный, актуальный и без дублей каталог забегов
**Source of truth:** `MVP.md` (при расхождении прав он)

## v1 Requirements

Требования первого релиза (MVP). Каждое отображено на одну фазу роадмапа.

### Discovery (источники и аудит VPS)

- [ ] **DISC-01**: Для каждого из 2–3 кандидатов в источники выполнена проверка **с VPS**: доступность, `robots.txt`, ToS, API, JSON и JSON-LD, sitemap и RSS, HTML, допустимые rate limits, антибот-защита, реальные поля, способ получения списка событий, наличие стабильного `external_id`, ссылки на регистрацию (команды выполняет владелец, см. DISC-03)
- [ ] **DISC-02**: Утверждён набор из 2–3 источников; неудобный или недоступный кандидат заменён другим; обход CAPTCHA и антибот-защиты не проектируется
- [ ] **DISC-03**: Аудит VPS выполнен только чтением и записан без секретов: назначение, `Listen`/`Allow` и `ufw` у `tinyproxy`; синхронизация часов; состояние Docker и Compose; swap; открытые порты. Никаких изменений на VPS. Команды выполняет владелец (у инструментов нет SSH-доступа): инструменты готовят команды только на чтение и анализируют присланный вывод
- [ ] **DISC-04**: Итоговый отчёт содержит для каждого источника способ получения данных, наличие `external_id`, частоту обновления, число запросов на цикл и ограничения, признак «содержит только российские соревнования» (основание для предварительного статуса кандидата на fallback `country_code = RU`; окончательное подтверждение — санити-проверка в Phase 3), а также перечень решений для Phase 3

### Foundation (основа)

- [ ] **FND-01**: Go-модуль (Go 1.27.1) с одним бинарником и подкомандами `bot`, `worker`, `migrate`, `healthcheck`
- [ ] **FND-02**: Схема PostgreSQL 17 из `MVP.md` (раздел 4) применяется миграциями `goose`, встроенными в бинарник; созданы все таблицы и индексы MVP
- [ ] **FND-03**: Доменные типы `event` и слой `store` на `pgx/v5` + `pgxpool`; весь SQL находится только в `internal/store`
- [ ] **FND-04**: Пакет `normalize`: `title_norm`, `city_key` (ASCII-slug, словарь синонимов), даты, время и часовой пояс (IANA), дистанции в метрах, отображение типа забега; `country_code` (ISO 3166-1 alpha-2; «Россия» и «Russia» → `RU`), `region` и `city` канонического события; `description` обрезается до 1000 символов по границе слова
- [ ] **FND-05**: Тестовая инфраструктура с реальной PostgreSQL 17: юнит-тесты `normalize` и интеграционный тест upsert
- [ ] **FND-06**: Конфигурация через переменные окружения; секреты не попадают в репозиторий (`.env` вне репозитория и в `.gitignore`)

### Ingestion (сбор данных)

- [ ] **ING-01**: `Fetch` с таймаутами, повторами (3 попытки, экспоненциальный backoff с jitter, `Retry-After`), лимитом размера ответа, rate limit на хост и `User-Agent` с контактом; значения конфигурируемы
- [ ] **ING-02**: `Parse` — чистая функция без сети; для каждого источника есть фикстуры в `testdata/` и golden-тесты
- [ ] **ING-03**: `Validate` отклоняет записи без обязательных полей или с датой вне `[сегодня−1 день, сегодня+3 года]`; отклонённые считаются
- [ ] **ING-04**: Upsert `source_events` идемпотентен по `(source_id, external_id)`; сохраняются `payload`, `content_hash`, `first_seen_at`, `last_seen_at`; неизменённая запись обновляет только `last_seen_at`
- [ ] **ING-05**: Создание канонического `events` и `event_distances` из `source_events`; поля выбираются по приоритету источника; `updated_at` меняется только при изменении канонических полей
- [ ] **ING-06**: Каждый запуск источника записывается в `ingest_runs` со статусом и счётчиками `fetched`, `parsed`, `rejected`, `out_of_scope`, `upserted`, `error`
- [ ] **ING-07**: Статус прогона `ok`/`suspect`/`failed` определяется автоматически (медиана последних 7 прогонов `ok`, доля отклонённых, даты вне диапазона, доля NULL); **прогоны `suspect` и `failed` ничего не применяют**; пороги конфигурируемы; есть ручное принятие нового базового уровня
- [ ] **ING-08**: Состояние наблюдения `source_events` (`active`/`missing`/`gone`) меняется только по здоровым прогонам и только для записей с `start_date ≥ сегодня`; `gone` влияет только на `events.is_listed`, **никогда не меняет `events.status`**; записи не удаляются
- [ ] **ING-09**: Планировщик запускает каждый источник раз в 6 часов со случайным сдвигом и общим таймаутом прогона, корректно останавливается по сигналу
- [ ] **ING-10**: Сырые ответы сохраняются на диск вне PostgreSQL с ограничением количества и TTL
- [ ] **ING-11**: `country_code` определяется так: явная страна источника (нормализованная); иначе fallback `RU` только для источника, который Phase 1 предварительно признала кандидатом (одни российские соревнования по структуре источника), после санити-проверки на реальных данных в Phase 3, окончательно подтверждающей это; запись с явно иной страной сохраняется в `source_events` с `match_state = out_of_scope` и события не создаёт; при неопределённой стране без подтверждённого источника молчаливого fallback нет
- [ ] **ING-12**: Добавление нового источника не требует изменения общего интерфейса ingestion и основной архитектуры pipeline; источник подключается через предусмотренный source adapter/parser contract (source-specific код добавлять разрешено); второй и (если утверждён) третий источники подключены
- [ ] **ING-13**: Описание события в БД не длиннее 1000 символов, изображения не скачиваются и не сохраняются (в схеме нет полей и файлов изображений); проверяется тестом на фикстуре с длинным описанием

### Bot (Telegram-поиск)

- [ ] **BOT-01**: Бот на long polling (`go-telegram/bot`) отвечает на `/start` и открывает сценарий «Найти забег»
- [ ] **BOT-02**: Пользователь фильтрует по дате (пресеты и месяц), городу (кнопки топ-10 из БД и текстовый ввод), дистанции (корзины) и типу; по умолчанию — будущие даты по всей России; регион в SQL есть, в интерфейсе нет
- [ ] **BOT-03**: Состояние фильтров хранится в `users.filters` с версией `filters_v`; устаревший callback обрабатывается понятным сообщением
- [ ] **BOT-04**: Список с пагинацией `LIMIT/OFFSET` по стабильному порядку `start_date, id`; листание через `editMessageText`; `callback_data` до 64 байт; роутинг по префиксу; на каждый callback есть `answerCallbackQuery`
- [ ] **BOT-05**: Карточка события: название, даты и время, город и адрес, тип, дистанции, короткое описание (до 1000 символов), кнопка регистрации, названия источников со ссылками
- [ ] **BOT-06**: В выдаче только события с `is_listed` и без `merged_into_id`; события со статусом `cancelled` и `postponed` **не скрываются** и показываются явно с пометкой `[ОТМЕНЁН]` или `[ПЕРЕНЕСЁН]` в списке и в карточке
- [ ] **BOT-07**: Админ-команда `/runs` (последние прогоны по источникам) доступна только `ADMIN_TG_IDS`
- [ ] **BOT-08**: О пользователях хранятся только Telegram ID и настройки поиска
- [ ] **BOT-09**: Ошибки Telegram API (блокировка бота, `TooManyRequests`, «message is not modified») обрабатываются без падения

### Deduplication (дедупликация)

- [ ] **DDP-01**: Кандидаты для сопоставления выбираются по стране и пересечению диапазонов дат
- [ ] **DDP-02**: Схожесть названий считается в Go (без `pg_trgm`); схема оценки и пороги **конфигурируемы**; значения 0,7 / 0,4 — стартовая гипотеза
- [ ] **DDP-03**: Высокая уверенность → автоматическая связь; средняя → отдельное событие плюс запись в `dedup_candidates`; низкая → отдельное событие
- [ ] **DDP-04**: Совпадение хоста и пути регистрации используется только как дополнительный сигнал и не является самостоятельным основанием для автоматического слияния
- [ ] **DDP-05**: Записи одного источника автоматически не склеиваются, если парсер не задал `group_key`; дистанция не участвует в идентичности события
- [ ] **DDP-06**: При слиянии `source_events` не удаляются, их `event_id` переключается на победителя, проигравшее событие получает `merged_into_id` и скрывается; цепочки слияний схлопываются до корня
- [ ] **DDP-07**: `/dupes` (только `ADMIN_TG_IDS`) показывает потенциальные дубли и позволяет подтвердить или отклонить; отклонённая пара повторно не предлагается
- [ ] **DDP-08**: Администратору приходит ежедневная сводка по ожидающим кандидатам вместо уведомления на каждую запись
- [ ] **DDP-09**: Пороги и схема оценки откалиброваны на размеченном наборе реальных пар (порядка 30–50); автоматическое слияние на нём не даёт ложных слияний
- [ ] **DDP-10**: Дистанции слитого события — объединение дистанций связанных `source_events` с допуском по метрам

### Monitoring (мониторинг)

- [ ] **MON-01**: Состояние здоровья и ошибок источника фиксируется в `ingest_runs` и структурных логах (последний статус, число подряд идущих сбоев, причина); Telegram-алертов в этой фазе нет
- [ ] **MON-02**: Структурные логи через `log/slog` во всех подкомандах
- [ ] **MON-03**: `bot` и `worker` пишут heartbeat раз в минуту, следят друг за другом (устарел больше 10 минут → алерт); подкоманда `healthcheck` и docker healthcheck работают
- [ ] **MON-04**: Алерты при недоступной PostgreSQL и сбое бэкапа; недоступность Telegram API фиксируется в логе, отправка повторяется с backoff
- [ ] **MON-05**: Администратор (`ADMIN_TG_IDS`) получает алерт в Telegram при `failed` и `suspect` прогонах и всплеске ошибок парсера; один алерт на смену состояния, напоминание через 24 часа

### Production (развёртывание)

- [ ] **PRD-01**: Docker Compose: `postgres` (PostgreSQL 17, том, порт наружу не публикуется, healthcheck), одноразовый `migrate`, `bot`, `worker` (`restart: unless-stopped`, ротация логов); образ на Go 1.27.1
- [ ] **PRD-02**: Хост подготовлен (каждое изменение только с отдельного разрешения владельца): плагин Compose, swap 1–2 ГБ, синхронизация часов, `ufw`, пользователь без `root`; обновление и перезагрузка — только по отдельному разрешению
- [ ] **PRD-03**: Ночной `pg_dump` с шифрованием (на VPS только публичный ключ, **ключ расшифровки не на VPS**) выгружается во внешнее хранилище; хранение 7 ежедневных и 4 еженедельных копий
- [ ] **PRD-04**: Восстановление из бэкапа проверено в отдельном контейнере, шаги записаны в runbook, определена периодичность проверок
- [ ] **PRD-05**: Внешний heartbeat (dead man's switch) настроен на случай падения хоста
- [ ] **PRD-06**: Runbook: развёртывание, бэкап и восстановление, реакция на алерты, обновление парсера при изменении вёрстки
- [ ] **PRD-07**: Судьба `tinyproxy` определена владельцем и (только если он подтвердит) выполнена; проект его не использует

## v2 Requirements

Отложено на после MVP, в текущий роадмап не входит.

### Данные

- **DATA-01**: Цена на `event_distances` (`price_minor`, `currency`), затем ценовые ступени
- **DATA-02**: `registration_status` события
- **DATA-03**: История изменений (`event_changes`)
- **DATA-04**: Сущность «серия» для ежегодных забегов
- **DATA-05**: События без метража (суточные, «6 часов»)

### Гео

- **GEO-01**: `lat/lon`, геокодинг с кешем
- **GEO-02**: Поиск «в радиусе N км»
- **GEO-03**: Регион как фильтр в интерфейсе

### Пользователи

- **USR-01**: Избранное
- **USR-02**: Уведомления о новых, перенесённых и отменённых забегах (очередь исходящих сообщений с лимитом)
- **USR-03**: Рекомендации, Mini App

### Платформа

- **PLT-01**: Другие страны и транслитерация ru↔en
- **PLT-02**: Курсорная пагинация при выдачах в десятки тысяч
- **PLT-03**: Prometheus и Grafana
- **PLT-04**: CI

## Out of Scope

Явные исключения, чтобы не возвращаться к ним без причины.

| Feature | Reason |
|---------|--------|
| Redis, Kafka, Elasticsearch, OpenSearch, PostGIS, Kubernetes | Преждевременная инфраструктура; PostgreSQL достаточно |
| Микросервисы | Один бинарник и один VPS достаточны |
| ML-сопоставление, эмбеддинги | Ручная очередь достаточна на масштабе MVP |
| Веб-админка | Хватает `/dupes` и `/runs` в боте |
| Автоматическая регистрация на забег | Вне ядра ценности, юридические риски |
| Копирование изображений и больших текстов | Авторские права; описание не длиннее 1000 символов |
| Сбор данных участников | Персональные данные; объект — только публичная информация о соревнованиях |
| Обход CAPTCHA и антибот-защиты | Недопустимо; источник с такой защитой заменяется |
| Слой `usecase` | Тонкий проброс без логики |
| Webhook и reverse proxy | Достаточно long polling |
| Использование `tinyproxy` для запросов к источникам | Не входит в архитектуру проекта |
