## Flagged assumptions (spec-less fallback)

- DDP-01: `Pass` оценивает только корневые события в выдаче со `start_date ≥ сегодня − 1` (UTC, реальные часы — сигнатура `Pass` из контракта без часов; тесты берут даты от `time.Now()`). Событие, у связанной строки которого `fields` ещё NULL (до первого прогона нового образа), не оценивается — выкат 05-08 делает повторный прогон Марафонца.
- DDP-03: включение `DEDUP_AUTO_MERGE` промотирует накопленные `pending` следующим `Pass` (`decided_by` NULL, Pitfall 12); отклонённые не промотируются.
- DDP-06: победитель — корень с меньшим id независимо от приоритета источников (приоритет — для полей, D-07); строки проигравшего получают `match_state` auto/manual.
- DDP-07: отклонение блокирует пару по корням; после легитимного слияния A с C пара (A∪C, B) тоже не предлагается — консервативно. Устаревшие `pending` удаляются; если пара снова пройдёт, строка создаётся заново с `notified_at` NULL и может снова попасть в сводку как новая.
- DDP-04 (через `Decide`): роль ссылки на пороге автослияния — по метке checkpoint (link-strict / link-as-planned), решение владельца.
- `MaxPerEvent` ограничивает только кандидатов; автослиянию нужен `UniquePartner` (у каждой стороны ≤ 1 партнёра со score ≥ High).
- Сериализация: запись прогонов всех источников, `Pass` и слияния из бота берут одну advisory-блокировку — запись источников идёт по очереди (секунды на прогон); потолок описан комментарием в `runner.go`.
- `CandidateByID` возвращает только `pending`; обработанный и несуществующий кандидат для бота неразличимы («Кандидат уже обработан»).
