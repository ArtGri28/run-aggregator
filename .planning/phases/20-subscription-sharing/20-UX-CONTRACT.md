# Phase 20: UX-контракт подписки и «Поделиться стартом»

**Статус:** утверждён владельцем 2026-10-20: «Контракт утверждаю, Q-1 (б), Q-2 и Q-3 по рекомендациям». «Поделиться» в Mini App — в Phase 21.
**Основа:** `20-CONTEXT.md` (D-01…D-13, утверждены 2026-10-20). Обозначения — как в `13-UX-CONTRACT.md`: тексты в HTML; `[подпись] → data`; ряды кнопок через ` | `; `url:` — кнопка-ссылка.

Каталог тестов — сохранённая страница Марафонца (133 беговых события, Россия), «сегодня» 2026-09-29. `{id}`, `{title}`, `{date}`, `{city}` — значения события; `{bot}` — имя бота из `getMe` (в тестах — `test_bot`); `{share}` — ссылка из раздела 2.

## 1. Принципы

1. Подписку включает только сам пользователь кнопкой. Никому ничего не задаём и не присылаем без нажатия.
2. Тексты не обещают полноты каталога, не говорят «регистрация открыта» и ничего не говорят о данных пользователя.
3. Экраны поиска, списков, меню, анкеты и профиля не меняются. Меняются только карточка (одна кнопка), «Мои настройки» (строка и кнопки подписки) и `/activity` (одна строка). Полный список изменённых эталонов — в разделе 6.

## 2. Ссылки

- Ссылка на старт: `https://t.me/{bot}?start=e_{id}`, где `{id}` — корень слияния на момент нажатия.
- Кнопка «Поделиться»: `https://t.me/share/url?url=<ссылка на старт>&text=<{title}>`, обе части в URL-кодировке.
- Метка входа: `https://t.me/{bot}?start=src_<метка>`, метка — `[a-z0-9_]{1,20}`. Иначе параметр не учитывается, и `/start` работает как обычно.

## 3. Callback и хранение

Новые callback — в существующем префиксе `s:` (настройки):

| data | Действие |
|---|---|
| `s:b:v<N>` | подписаться или обновить подписку текущими фильтрами версии N; версия устарела — «Кнопка устарела — нажмите /start», ничего не пишется |
| `s:u:o` | отписаться с экрана настроек; экран настроек перерисовывается |
| `s:u:d` | отписаться из сообщения подписки; в сообщении пропадает кнопка «🔕 Отписаться», текст остаётся |
| `s:l` | «Показать все в поиске»: фильтры поиска заменяются копией из подписки, приходит список новым сообщением |

Карточка, открытая по ссылке или из сообщения подписки, — `e:{id}:0`. Страница 0 значит, что источник — сообщение без списка: карточка приходит новым сообщением, а «⬅️ Назад» ведёт в главное меню (`m`).

Схема — `00013_subscriptions.sql`, утверждена. Копия фильтров — тот же JSON, что `users.filters`, без ключей `date` и `dates`.

## 4. Экраны бота

### N-1 Карточка — кнопка «Поделиться»

Ряд «⭐ В избранное» получает вторую кнопку. Остальное не меняется.
```
[⭐ В избранное] | [📤 Поделиться] → url:{share}
```
То же у «✖️ Убрать из избранного» (`w:x:{id}`). Строку «🔗 Регистрация», если она есть, и прочие ряды не трогаем.

### N-2 Карточка по ссылке

`/start e_{id}` — карточка новым сообщением (`sendMessage`), кнопки:
```
[🔗 Регистрация] → url:…          (если есть)
[⭐ В избранное] → w:a:{id} | [📤 Поделиться] → url:{share}
[📝 Сообщить об ошибке] → q:o:{id}   (если заявки включены)
[⬅️ В меню] → m
```
- Новый пользователь: бот создаёт строку `users`, как при поиске, но предложение анкеты не показывает. Анкету предложит следующий обычный `/start`.
- События нет, оно скрыто или его вид спорта выключен: «Событие больше не доступно» с кнопкой «⬅️ В меню» → `m`.
- `{id}` не число: обычный `/start`.

### N-3 «Мои настройки» без подписки

К экрану добавляется одна кнопка над «✏️ Изменить фильтры»:
```
[🔔 Подписаться на новые старты по этим фильтрам] → s:b:v<N>
[✏️ Изменить фильтры] → f:s:v<N>
[🔄 Сбросить настройки] → s:r:o:v<N>
[⬅️ Назад] → m
```
Нажатие — уведомление «🔔 Подписка включена», экран перерисовывается как N-4.

### N-4 «Мои настройки» с подпиской

Последней строкой текста — «🔔 Подписка на новые старты: включена». Если фильтры поиска отличаются от копии в подписке (без учёта дат), к строке добавляется « (по прежним фильтрам)», и появляется кнопка обновления:
```
⚙️ <b>Мои настройки</b>

🌍 Страна: 🇷🇺 Россия
…
🔎 Активно фильтров: 1 из 5

🔔 Подписка на новые старты: включена
---
[🔕 Отписаться] → s:u:o
[✏️ Изменить фильтры] → f:s:v<N>
[🔄 Сбросить настройки] → s:r:o:v<N>
[⬅️ Назад] → m
```
Если фильтры отличаются:
```
🔔 Подписка на новые старты: включена (по прежним фильтрам)
---
[🔔 Подписаться по этим фильтрам] → s:b:v<N>
[🔕 Отписаться] → s:u:o
…
```
«🔕 Отписаться» — уведомление «🔕 Подписка отключена», экран как N-3.

### N-5 Сообщение подписки

Новое сообщение в понедельник после 10:00 по Москве, если есть новые старты. Без звука с 23:00 до 08:00 по Москве — как у избранного.
```
🔔 <b>Новые старты по вашей подписке</b>

🏃 Бег
⚙️ Фильтры: Москва · 🟡 10–21 км
---
[{dd.mm} · {city} · {title}] → e:{id}:0      (до 10 кнопок, по дате)
[🔎 Показать все в поиске] → s:l              (только если стартов больше 10)
[🔕 Отписаться] → s:u:d
```
- Под заголовком — вид спорта подписки и её фильтры строкой «⚙️ Фильтры: …», точно как над списком поиска. Если фильтров нет, этой строки нет. Если стартов больше 10, дальше строка «Показаны 10 из {n}».
- Кнопки стартов — как в списке поиска: тот же формат и обрезка.
- После отправки время отправки записывается в подписку. Следующее сообщение — только о стартах, появившихся после него.
- 403 «бот заблокирован» — подписка удаляется, как избранное у заблокировавших.

### N-6 Отписка из сообщения

`s:u:d` — уведомление «🔕 Подписка отключена», клавиатура сообщения без ряда «🔕 Отписаться», текст прежний. Уже отписан — то же уведомление, без ошибки.

### N-7 «Показать все в поиске»

`s:l` — фильтры поиска заменяются копией из подписки, даты сбрасываются. Список приходит новым сообщением, первая страница — экран списка без изменений. Подписки нет — «Кнопка устарела — нажмите /start».

### N-8 `/activity`

После строки «Новых за 7 дней» — строка «🔔 Подписаны на новые старты: {n}». После блока «Действия за 7 дней» — блок, только если за 7 дней были входы по меткам:
```

🔗 Пришли по ссылкам за 7 дней
share — 3
vk — 1
```
Метки — по убыванию числа, не больше 10. Числа точные. Вход по ссылке на старт (`e_`) считается как метка `share`.

## 5. Mini App

Кнопка «Поделиться» в Mini App (D-12) знает ссылку только с именем бота. У процесса webapp нет токена бота, поэтому `getMe` он вызвать не может (так задумано в Phase 15). Вопрос Q-1 ниже.

## 7. Сценарии

Каждый шаг — тест на фиктивном Bot API с PostgreSQL и сверка с эталоном.

### S-62 Подписка в настройках — тест `TestS62Subscribe`
N-3 (`s62_settings`); «🔔 Подписаться…» — N-4 (`s62_subscribed`); смена страны — N-4 «по прежним фильтрам» (`s62_changed`); «🔕 Отписаться» — N-3; устаревшая версия — тост «Кнопка устарела», в базе ничего.

### S-63 Сообщение подписки — тест `TestS63Digest`
Нет новых — нет сообщения. 3 новых — N-5 (`s63_digest`). 12 новых — N-5 с «Показаны 10 из 12» и «🔎 Показать все в поиске» (`s63_digest_more`). Повтор в ту же неделю — нет второго. 403 — подписка удалена.

### S-64 Из сообщения подписки — тест `TestS64DigestActions`
Кнопка старта — N-2 новым сообщением (`s64_card`); «🔎 Показать все…» — список новым сообщением (`s64_list`); «🔕 Отписаться» — N-6 (`s64_unsubscribed`).

### S-65 Ссылка на старт — тест `TestS65ShareLink`
Карточка с «📤 Поделиться» (`s65_card_share`); `/start e_{id}` новым пользователем — N-2 (`s65_link_new`), анкета не предложена, следующий `/start` её предлагает; слитое событие — карточка корня; скрытое — «Событие больше не доступно» (`s65_link_gone`).

### S-66 Метки входа — тест `TestS66Sources`
`/start src_vk` — главное меню, счётчик `src_vk`; плохая метка — обычный `/start`, счётчика нет; `/activity` с блоком меток (`s66_activity`).

## 8. Требования (предложение)

- **SUB-01:** Подписка включается только кнопкой; хранится копия фильтров без дат; одна на пользователя. Критерий: S-62.
- **SUB-02:** Не больше одного сообщения подписки в неделю, только о стартах, появившихся после прошлого сообщения или включения; без новых — нет сообщения. Критерий: S-63.
- **SUB-03:** Отписка кнопкой в каждом сообщении и в настройках; 403 удаляет подписку. Критерий: S-62…S-64.
- **SUB-04:** «Поделиться» в карточке бота; ссылка открывает карточку и новому пользователю, анкета не теряется. Критерий: S-65.
- **SUB-05:** Метки входа считаются без привязки к пользователю и видны в `/activity`. Критерий: S-66.
- **SUB-06:** В логах нет Telegram ID, фильтров подписки и названий стартов; BOT-08 описывает хранимое. Критерий: тест логов, текст BOT-08.

## 9. Вопросы владельцу

- **Q-1. «Поделиться» в Mini App.** Webapp не знает имени бота. Варианты:
  - **(а)** строка `BOT_USERNAME=<имя бота>` в `.env` и в `docker-compose.yml` для webapp. Это переустановка пакета (`INSTALL`), строку вводишь ты;
  - **(б)** перенести кнопку Mini App в Phase 21 вместе с вкладкой «Мой календарь» — там её удобно сделать тем же выкатом.
  
  Рекомендую (б): Phase 20 выкатывается без переустановки пакета.
- **Q-2. Кнопка «Поделиться» в одном ряду с «⭐»** — или отдельным рядом под ней? Рекомендую в одном ряду: карточка не становится длиннее.
- **Q-3. Строку подписки в N-4** показывать в конце текста — так ок?

## 10. Не входит

- подписка в Mini App (Phase 21);
- несколько подписок;
- рассылка администратора (Phase 10);
- inline-режим;
- картинка-превью ссылки.

## 11. Правка 2026-10-20: пояснение подписки

После production-проверки владелец попросил, чтобы человек знал, как работает подписка, когда и как часто приходит сообщение. Владелец: «Утверждаю все три».

1. **N-3** — последним абзацем текста:
```
🔔 Подписка на новые старты: раз в неделю, по понедельникам, бот пришлёт старты, которые появились в каталоге по этим фильтрам. Если новых не будет — сообщения не будет.
```
2. **N-4** — под строкой «🔔 Подписка на новые старты: включена» (с « (по прежним фильтрам)», если фильтры отличаются):
```
Сообщение приходит по понедельникам после 10:00 по Москве — только если появились новые старты по этим фильтрам. Отписаться можно здесь или кнопкой в самом сообщении.
```
3. **Уведомление после «Подписаться»:** «🔔 Подписка включена. Новые старты — по понедельникам».

Изменённые эталоны: 8 экранов «Мои настройки» и `s62_settings`, `s62_subscribed`, `s62_changed`.
