# 17-02: выкат MyRace вместе с этапом А Mini App

Цель: один выкат образа с `main` (MyRace из 17-01 и код Mini App фазы 15), Mini App остаётся выключенным; источник MyRace начинает работать по токену из `.env` сервера. Миграций нет.

**Каждый шаг на production — только по отдельному разрешению владельца на этот шаг.** Команды выполняет владелец; токен MyRace вводится только в root-консоли и никуда не пересылается.

## Предусловия

- `PRODUCTION CHECK:` фазы 14 записан (2026-10-14, `15d793a`).
- `main` = `origin/main`, дерево чистое; тесты 512 PASS, 0 FAIL, 0 SKIP.
- Домен для этого выката не нужен: `COMPOSE_PROFILES` в `.env` не добавляется.

## Шаги

1. **Состояние копий.** `agg backup-status` → `STATUS OK`, `usable=yes` (лог `p17-backup-status.log`). Миграций нет — свежая копия перед deploy не обязательна.
2. **Состояние до.** `agg verify` (лог `p17-before-verify.log`): запомнить `events_listed=`, `events_merged=`, `source_run=`.
3. **Пакет.** `SSH_CONFIG=~/.ssh/run_agg.conf deploy/ship.sh run-agg-vps` — ожидаемая остановка на сверке SHA256 (изменены `docker-compose.yml` и скрипты фазы 15).
4. **Установка пакета.** Root-консоль: однострочник из вывода `ship.sh`, слово `INSTALL`.
5. **Образ.** Снова `ship.sh` → `AGG LOAD OK`, `IMAGE_TAG=<TAG>` (лог `p17-ship.log`).
6. **Токен.** Root-консоль, одной строкой; токен вводится скрытно, команда печатает только число строк (ожидается `1`):
   `test -s /opt/aggregator/.env && read -rsp 'MYRACE_TOKEN: ' S && echo && [ -n "$S" ] && T=$(mktemp /opt/aggregator/.env.XXXXXX) && { grep -v '^MYRACE_TOKEN=' /opt/aggregator/.env; printf 'MYRACE_TOKEN=%s\n' "$S"; } > "$T" && chmod 600 "$T" && mv "$T" /opt/aggregator/.env; unset S; grep -c '^MYRACE_TOKEN=' /opt/aggregator/.env`
7. **Preflight.** `agg preflight <TAG>`: `DEPLOY PREFLIGHT DONE`, `COMPOSE_PROFILES: нет (Mini App выключен)`, права `.env` 600, строк `ВНИМАНИЕ` нет.
8. **Deploy.** `printf 'DEPLOY\n' | … agg deploy <TAG>` (лог `p17-deploy.log`).
9. **Проверка.** Через две минуты `agg verify` (лог `p17-deploy-verify.log`): `DEPLOY VERIFY OK`, бот и воркер на `<TAG>` `healthy`, `webapp_profile=off`, `published=none`, `CHECK ports-only-caddy: OK`, `CHECK ports-caddy-80-443: OK`; `events_listed`, `events_merged` и автослияние — как до выката. В логе воркера — строка `next run` с `"source":"myrace"`.
10. **Первый прогон MyRace.** Ожидается статус `suspect` с причиной «первый прогон источника — требуется принятие» и сообщение администратору с кнопкой. Ожидаемые цифры на 2026-10-14: разобрано около 34, вне каталога около 4, в каталог около 30 (10 из них уже есть у других источников — уйдут в ручную очередь пар). Если цифры близки — владелец принимает прогон кнопкой. `failed` с `HTTP 401` — токен не принят: прогон не принимать, повторить шаг 6.
11. **После принятия.** `agg verify` (лог `p17-after-accept-verify.log`) и запрос `run_counts=` из `deploy/README.md`: строка `myrace` с `created` около 30; `events_listed` выросло на число новых событий минус отложенные в очередь пар; `dedup_candidates` `pending` вырос на число найденных пар; автослияние выключено.
12. **Telegram.** Поиск одного из новых стартов (например, «Таганай» или «Карабаш») — карточка с источником «MyRace» и ссылкой на страницу события.

После шага 12 — `ROLLOUT DONE` и сообщение техлиду MyRace о публикации (текст готовлю отдельно, без токена).

## Нарушения и откат

- `changed` у прежних источников сопоставим с числом их записей, или `events_merged` изменилось без решения владельца — остановиться, решать об откате.
- Откат — `agg rollback` (миграций нет); `COMPOSE_PROFILES` в `.env` нет, поэтому откат к образу без `webapp` безопасен. Строку `MYRACE_TOKEN` прежний образ просто не читает.
- Выключить только MyRace без отката — удалить строку `MYRACE_TOKEN` из `.env` и выполнить deploy того же тега. Прогоны прекращаются, но уже записанные события MyRace остаются в каталоге: наблюдение за пропавшими записями идёт только в прогонах источника. Скрыть их — отдельным решением.
