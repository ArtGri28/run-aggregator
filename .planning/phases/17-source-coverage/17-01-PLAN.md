# 17-01: источник MyRace по API

Цель: адаптер `myrace`, читающий `GET /api/1.0/calendar` с токеном партнёра, по решениям D-01…D-08 из `17-CONTEXT.md`. Только код и тесты; выкат — отдельным планом 17-02 после `PRODUCTION CHECK` фазы 14 и разрешений владельца.

## Задачи

### 1. Заголовок авторизации в загрузчике
`internal/ingest/fetch.go`: минимальное расширение — `Get` получает необязательный заголовок `Authorization` (например, `GetAuth(ctx, url, delay, auth string)`, а `Get` вызывает его с пустой строкой). При непустом `auth` — `Accept: application/json`. Тексты ошибок и `RawDoc.URL` токена не содержат (он только в заголовке). Тест: заголовок дошёл до сервера; при 401 ошибка без повтора и без токена в тексте.

### 2. Пакет `internal/ingest/sources/myrace`
- `Code = "myrace"`, `ListURL = "https://myrace.info/api/1.0/calendar?limit=100"`, `CrawlDelay = 1 * time.Second`, `maxPages = 50`.
- `New(f *ingest.Fetcher, token string)`.
- `Fetch`: первая страница без `page_token`, затем по `next_page_token`, пока он есть; каждая страница — отдельный `RawDoc`. Больше `maxPages` — ошибка прогона, а не усечение. Ошибка любой страницы — ошибка прогона.
- `Policy`: `CountryFallback: normalize.NoFallback` (D-01: событие без страны — вне каталога).
- `Parse` (чистая): разбор JSON страницы; ответ без массива `events` — `ErrStructureNotFound`. Событие без видов спорта из D-02 пропускается (фильтр источника, как фильтр «Бег» в адресе Tristyle). Для остальных одна запись:
  - `ExternalID` = `id`, `URL` и `RegistrationURL` = `url` (D-05), `Title` = `name`;
  - `Date` = `start_date`, `EndDate` = `end_date`, если отличается;
  - `City` = `location.city`, `Country` = `location.country` (без страны — пусто, D-01);
  - `TypeLabel` по D-03 (`trail`, `obstacle` или пусто → `other`); при нескольких видах — `obstacle` важнее `trail`, `trail` важнее `running`;
  - `Distances` = названия активностей с видом спорта из D-02 (или без вида), через запятую — разбор километров делает существующий `normalize.Distances` (D-04);
  - `Sport` пусто (бег).
- Порядок полей payload и `content_hash` — как у остальных источников.

### 3. Регистрация
- `cmd/aggregator/main.go`, `newSources`: `myrace.New(f, token)` добавляется, только если `MYRACE_TOKEN` непуст (D-07); токен читается там же, где остальное окружение, и нигде не логируется.
- `internal/bot/list.go`, `sourceNames`: `"myrace": "MyRace"`.
- `docker-compose.yml`: `MYRACE_TOKEN: ${MYRACE_TOKEN:-}` в якоре `x-app-env` (общий для bot и worker: принятие прогона кнопкой из бота строит тот же список источников). Сервису `webapp` не передаётся.
- `.env.example`: строка `MYRACE_TOKEN=` с пояснением; пусто — источник выключен.

### 4. Тесты
- `testdata/`: две страницы, собранные из образца 2026-10-14 (по одному событию на каждый случай: трейл, `running`, с препятствиями, только вело — пропуск, без страны, Армения, абонемент с прошедшей датой, активности с шифрами и без километров, событие без активностей); `next_page_token` только у первой.
- Golden-тест `Parse` и `Prepare` по образцу heroleague/tristyle.
- Тест `Fetch` на `httptest.Server`: проходит обе страницы, передаёт заголовок, останавливается на `maxPages`, 401 — ошибка прогона.
- Проверка `grep`: строки `MYRACE_TOKEN` значение нигде в репозитории не задано, кроме пустого в `.env.example`.
