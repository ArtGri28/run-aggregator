## 2. Сценарии пользователя

1. **Первый вход:** `/start` → главное меню (одна кнопка) → сводка → «Показать N» → список → карточка → «К списку» → «К фильтрам».
2. **Сужение поиска:** сводка → подменю (дата/город/дистанция/тип/страна) → выбор → сводка с обновлённым N.
3. **Город текстом:** любое сообщение без `/` трактуется как город (состояния «жду ввод» нет); найден → новое сообщение со сводкой; не найден → похожие по префиксу.
4. **Пустая выдача:** «Ничего не нашлось» → «Снять …» → сводка.
5. **Повторный `/start`:** фильтры сохраняются (D-17 Phase 4); меню приходит новым сообщением, старые сообщения с кнопками остаются в чате.
6. **Старое сообщение:** кнопки предыдущих сообщений продолжают работать — см. раздел 3.

## 3. Callback

| Формат | Кто создаёт | Меняет `filters`/`filters_v` | Меняет `last_seen_at` | При устаревшем состоянии |
|---|---|---|---|---|
| `f:s`, `f:d`, `f:c`, `f:b`, `f:t`, `f:k` (открыть) | сводка, «Назад», «К фильтрам» | нет | **да** (`touchUser` в `Store.Filters`) | версии нет — всегда работает |
| `f:d:<v>`, `f:c:<v>`, `f:b:<i>`, `f:t:<v>`, `f:k:<v>`, `f:x[:поле]` (изменить) | подменю, сводка, пустая выдача | **да** | да (`UpdateFilters`) | версии нет — старая кнопка меняет текущие фильтры (`TestAuditUsersTouch`) |
| `p:<стр>:v<N>` | сводка, список, карточка | нет | **да** | чужая версия → 1-я страница актуальной выдачи и уведомление |
| `e:<id>:<стр>:v<N>` | список | нет | да (`cardPlaceStyle` → `Filters`) | версия не проверяется; скрытое/слитое событие → «Событие больше не доступно» |
| неизвестный префикс | — | нет | нет (`onDefault` не обращается к БД) | «Кнопка устарела — нажмите /start» |
| неразборчивый `f:`/`p:`/`e:` | — | нет | нет (`cb` отвечает до обращения к БД) | «Кнопка устарела — нажмите /start» |
| `r:…`, `d:…` | алерты, `/dupes` | — | — | вне объёма Phase 8 (D-07) |

Все `callback_data` в снимках ≤ 64 байт (`checkCallbackLengths`).
