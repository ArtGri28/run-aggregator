# Phase 8 Plan 03: версия в `f:`, устаревшие кнопки, внутренняя ошибка

**Статус: complete (локально).** Реализован раздел 5 утверждённого контракта (P1, P2, P3). Миграций нет, схема `users` не менялась. Telegram API не вызывался, VPS и production не затрагивались. Коммит делает владелец.

UX-02 выполняется по частям (08-03…08-06); статус в REQUIREMENTS.md — в 08-07.

## Что сделано

- **Хранилище** (`internal/store/users.go`): `PeekFilters` — фильтры и версия без единой записи (нет пользователя — `{}`, версия 0, строка не создаётся); `UpdateFiltersAt` — изменение только при совпавшей версии: `SELECT … FOR UPDATE` и запись в одной транзакции, иначе `ErrStaleFilters` и ничего не пишется.
- **Формат** (`callback.go`): `f:<вид>[:значение]:v<N>`; `f:` без версии — `Legacy` (кнопки старых сообщений), `encode` его не создаёт; `v0` допустима.
- **Правила раздела 5** (`filters.go`, `list.go`):
  - меняющая кнопка — `updateAt`: без версии или с чужой версией — «Кнопка устарела — нажмите /start», сообщение не правится, записей нет;
  - навигация — `cbState`: актуальная кнопка отмечает активность (`last_seen_at`), устаревшая показывает экран по текущему состоянию без записи; для `p:` — первая страница и «Фильтры изменились — показываю актуальную выдачу»; пользователя нет — экран по умолчанию с кнопками `v0`;
  - `stamp` проставляет версию во все кнопки `f:` перед показом (`/start`, фильтры, список, ответ на текст).
- **Внутренняя ошибка** (`bot.go`, `cb`): паника обработчика и ошибка БД отвечают «Что-то пошло не так, попробуйте ещё раз»; логи `callback internal error prefix=<буква>` и `callback stale prefix=<буква>` — разные строки, без данных пользователя (при панике — стек).
