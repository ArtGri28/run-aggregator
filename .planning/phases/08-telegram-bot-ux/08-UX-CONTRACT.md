**Дополнен 2026-10-04** ответом владельца «Утверждаю вариант Б» (08-VERIFICATION.md, пробелы 1–2; план 08-09): два ответа на текстовое сообщение, которых не было в аудите и контракте, получили навигацию — E-08, S-05 шаги 6 и 7.
**Основа:** 08-AUDIT.md (снимки `b165c10`, проблемы P1–P10), 08-CONTEXT.md (D-01…D-16), решения Phase 4 (04-CONTEXT.md).
**Обозначения:** `<N>` — текущая версия фильтров пользователя (`users.filters_v`); `{…}` — подстановка; снимок — эталон `internal/bot/testdata/screens/<имя>.txt`. Тексты экранов — HTML (`parse_mode: HTML`), если не сказано иначе.

## 1. Принципы

1. **Один возврат.** На каждом экране, кроме главного меню, ровно одна кнопка возврата — подпись «⬅️ Назад», последняя строка клавиатуры, ведёт к родителю по дереву навигации (раздел 2). Исключение — пустая выдача и «Событие больше не доступно»: там возврат — единственный путь, подпись та же. Без клавиатуры остаются только ответы обычным текстом на команду, кроме `/start` («Нажмите /start, чтобы найти забег», P9), и на текстовое сообщение при внутренней ошибке («Что-то пошло не так, попробуйте ещё раз»); остальные ответы на текст подчиняются этому принципу.
2. **Экран меняется на месте.** Кнопки правят текущее сообщение (`editMessageText`); новое сообщение — только ответ на `/start` и на текст.
3. **Данные меняет только явное действие** с актуальной кнопкой. Устаревшая кнопка ничего не пишет (раздел 5).
4. **Уведомление на кнопку** (answerCallbackQuery) — ровно одно на нажатие; текст — только там, где указан в контракте.

## 2. Дерево навигации

```
Главное меню (/start, «⬅️ Назад» со сводки и настроек)
├── Поиск (сводка фильтров)
│   ├── Страна* / Город / Дата / Дистанция / Тип  → «⬅️ Назад» → Поиск
│   ├── Список → Карточка → «⬅️ Назад» → Список (та же страница)
│   │   └── «⬅️ Назад» → Поиск
│   ├── Пустая выдача → «⬅️ Назад» → Поиск
│   └── Сброс? (подтверждение) → «⬅️ Назад» → Поиск
└── Мои настройки
    ├── «✏️ Изменить фильтры» → Поиск
    └── Сброс? (подтверждение) → «⬅️ Назад» → Мои настройки
```
\* «Страна» — только если в каталоге больше одной страны или страна выбрана явно (как в `b165c10`).

## 3. Формат callback (P1)

| Вид | Формат | Меняет данные | Версия |
|---|---|---|---|
| главное меню | `m` | нет | не нужна (экран не зависит от фильтров) |
| открыть поиск / подменю | `f:<s\|d\|c\|b\|t\|k>:v<N>` | нет | да |
| изменить фильтр | `f:<d\|c\|b\|t\|k>:<значение>:v<N>` | да | да |
| снять один фильтр (пустая выдача) | `f:x:<d\|c\|b\|t\|k>:v<N>` | да | да |
| страница списка | `p:<стр>:v<N>` | нет | да (как в `b165c10`) |
| карточка | `e:<id>:<стр>:v<N>` | нет | да (как в `b165c10`) |
| мои настройки | `s:o:v<N>` | нет | да |
| спросить сброс | `s:r:<o\|f>:v<N>` (`o` — из настроек, `f` — из поиска) | нет | да |
| подтвердить сброс | `s:y:<o\|f>:v<N>` | да | да |
| админские `r:`, `d:` | без изменений (D-07) | — | — |

- Версия — всегда последнее поле `v<N>`, как у `p:` и `e:`.
- Длина ≤ 64 байт проверяется при создании кнопки (`encode`); кнопка, которая не помещается, не показывается (правило `b165c10`). Для кнопки города это значит: ключ города ≤ 64 − 4 (`f:c:`) − длина `:v<N>` байт. Тест: все ключи городов фикстур помещаются при `N` до 99999.
- Прежний `f:x` (сбросить всё со сводки без подтверждения) больше не создаётся.

## 4. Экраны

Неизменённые экраны указаны ссылкой на снимок аудита; меняется только перечисленное.

### E-01 Главное меню (`/start` — новое сообщение; `m` — правка)
```
🏃 <b>КАТАЛОГ ЗАБЕГОВ</b>

Найди свой следующий старт!
---
[🔎 Найти забег] → f:s:v<N>
[⚙️ Мои настройки] → s:o:v<N>
```
`/start` фильтры не сбрасывает (D-17 Phase 4).

### E-02 Поиск (сводка)
Текст — как `summary_default` / `summary_filtered`. Клавиатура:
```
[🌍 Страна] → f:k:v<N>                      (если показывается страна)
[📍 Город] → f:c:v<N> | [📅 Дата] → f:d:v<N>
[📏 Дистанция] → f:b:v<N> | [🏃 Тип] → f:t:v<N>
[🔎 Показать {n}] → p:1:v<N>
[🔄 Сбросить] → s:r:f:v<N>
[⬅️ Назад] → m
```

### E-03…E-07 Подменю даты, города, дистанции, типа, страны
Тексты и кнопки выбора — как `date_menu`, `city_menu`, `bucket_menu`, `type_menu`, `country_menu`; в каждой кнопке добавляется `:v<N>`. Последняя строка — `[⬅️ Назад] → f:s:v<N>`. В подменю дистанции кнопка «Готово» заменяется на «⬅️ Назад» (выбор применяется сразу, как и раньше; экран остаётся на месте после переключения корзины).

### E-08 Город текстом
- Найден — новое сообщение E-02 (как `city_text_found`).
- Не найден — новое сообщение (P8, раздел 7):
```
В каталоге нет забегов в «{ввод}»
{если есть подсказки:}
Возможно, вы имели в виду:
---
[{Город} ({n})] → f:c:{key}:v<N>        (до 5, по убыванию числа событий)
[📍 Выбрать из списка] → f:c:v<N>
[⬅️ Назад] → f:s:v<N>
```
- При «всех странах» город текстом не выбирается (как в `b165c10`) — новое сообщение, обычный текст (дополнение 2026-10-04):
```
Сначала выберите страну
---
[🌍 Страна] → f:k:v<N>
[⬅️ Назад] → f:s:v<N>
```
- Из текста не получается ключ города (например «!!!») — новое сообщение, обычный текст (дополнение 2026-10-04):
```
Не понял название города — попробуйте иначе или выберите из списка
---
[📍 Выбрать из списка] → f:c:v<N>
[⬅️ Назад] → f:s:v<N>
```
  Оба ответа фильтры и `filters_v` не меняют; кнопки несут текущую версию.
- Команда, кроме `/start` (например `/foo`), — как `city_text_command` (обычный текст «Нажмите /start, чтобы найти забег», без кнопок) — без изменений (P9 не входит).

### E-09 Список
Как `list_page1` с изменениями: дата строки — по P7 (раздел 6); последняя строка — `[⬅️ Назад] → f:s:v<N>` вместо «⬅️ К фильтрам».

### E-10 Карточка
Как `card` / `card_cancelled`; последняя строка — `[⬅️ Назад] → p:{стр}:v<N>` вместо «⬅️ К списку».

### E-11 Событие недоступно
`Событие больше не доступно` + `[⬅️ Назад] → p:{стр}:v<N>`.

### E-12 Пустая выдача
Как `empty_hints` / `empty_pick_country`: кнопки «Снять …» (`f:x:<поле>:v<N>`) и «🌍 Выбрать страну» (`f:k:v<N>`) без изменений; последняя строка — `[⬅️ Назад] → f:s:v<N>`. «Снять …» — явное действие над одним фильтром, без подтверждения.

### E-13 Мои настройки (новый, P4)
```
⚙️ <b>МОИ НАСТРОЙКИ</b>

Поиск использует эти параметры:
🌍 Страна: {страна или «🌍 Все страны»}
📍 Город: {город или «Все города»}
📅 Дата: {…}
📏 Дистанция: {…}
🏃 Тип: {…}
---
[✏️ Изменить фильтры] → f:s:v<N>
[🔄 Сбросить настройки] → s:r:o:v<N>
[⬅️ Назад] → m
```
Строка страны показывается всегда. Значения — теми же подписями, что в сводке. Только существующие данные `users.filters` (D-06).

### E-14 Подтверждение сброса (новый, P5)
```
Сбросить настройки поиска?

Станет: страна по умолчанию, все города, все будущие даты, любая дистанция, любой тип.
---
[✅ Да, сбросить] → s:y:{o|f}:v<N>
[⬅️ Назад] → s:o:v<N>   (из настроек)  |  f:s:v<N>   (из поиска)
```
После подтверждения — экран, с которого пришли (E-13 или E-02), с новыми значениями; уведомление «Настройки сброшены». Если настройки уже по умолчанию — то же, `filters_v` не растёт.

## 5. Устаревшие и неизвестные кнопки, внутренняя ошибка (P1, P2, P3)

Кнопка **устаревшая**, если её `v<N>` не равна текущей `filters_v`, в ней нет версии (формат `b165c10`) или пользователя нет в `users`.

| Случай | Что видит пользователь | Запись в БД |
|---|---|---|
| актуальная кнопка | экран по контракту | разрешена: `filters`, `filters_v` (при изменении), `last_seen_at` |
| устаревшая, меняющая данные (`f:<вид>:<значение>`, `f:x:…`, `s:y:…`, старый `f:x`) | сообщение не меняется; уведомление «Кнопка устарела — нажмите /start» | **никакой** (ни одной колонки `users`, включая `last_seen_at`; `events` не меняются) |
| устаревшая, только навигация (`f:<вид>` без значения, `p:`, `e:`, `s:o`, `s:r`) — совместимость (D-09) | экран по текущему состоянию с новыми кнопками; для `p:` — первая страница и уведомление «Фильтры изменились — показываю актуальную выдачу» (как в `b165c10`) | **никакой**: чтение без `touchUser`; если пользователя нет — значения по умолчанию, строка не создаётся |
| неизвестный или неразборчивый callback | сообщение не меняется; уведомление «Кнопка устарела — нажмите /start» | никакой |
| внутренняя ошибка (ошибка БД, panic обработчика) | сообщение не меняется; уведомление «Что-то пошло не так, попробуйте ещё раз» | транзакция откатывается |

- **P2, `last_seen_at`:** обновляется только `/start`, текстовым сообщением и актуальной кнопкой. Устаревшая и неизвестная кнопка не пишут ничего — это проверяется сравнением строки `users` целиком (`to_jsonb`) и таблицы `events` до и после нажатия.
- **P1, проверка версии и запись** — в одной транзакции под блокировкой строки пользователя: между проверкой и изменением нет окна.
- **P3, логи:** `callback stale prefix=<буква>` и `callback internal error prefix=<буква>` — разными строками; данных пользователя и текста кнопок в логе нет. При panic процесс продолжает работу (recoverMW), ответ — текстом внутренней ошибки, а не пустой.

## 6. Дата в списке (P7) — **включается**

- Строка списка: `ДД.ММ`, если год события равен текущему году (Москва), иначе `ДД.ММ.ГГГГ`.
- Пример (сегодня 29.09.2026): `02.10 · Чулково · …`, `04.09.2027 · Пермь · …`.
- Карточка не меняется (в ней уже полная дата с годом).
- Если владелец не включает P7 — строка остаётся `ДД.ММ`, раздел удаляется.

## 7. Подсказки города (P8) — **включается, без изменения нормализации**

- Нормализация ключа (`normalize.CityKey`, синонимы) **не меняется**; выбор города по точному совпадению — как в `b165c10`.
- Подсказки при «не найдено» ищутся в стране фильтров по двум правилам (объединение, без повторов): (1) ключ города начинается с ключа ввода или содержит `-<ключ ввода>` (как сейчас); (2) **название города начинается с введённого текста без учёта регистра** (новое; «Моск» → Москва).
- До 5 подсказок, по убыванию числа будущих событий, затем по ключу.
- Ввод короче 2 символов — подсказок нет (как сейчас для слишком коротких ключей).
- Кнопка «📍 Выбрать из списка» добавляется всегда (E-08).
- Затрагивает `internal/store/facets.go` (`SimilarCities`) — при утверждении добавляется в `files_modified` плана 08-04.
- Если владелец не включает P8 — подсказки только по правилу (1), раздел сокращается до кнопки «Выбрать из списка».

## 8. Сценарии

Каждый шаг — тест `TestSxx<Имя>` на фейковом Bot API и сверка со снимком; имя эталона — `sxx_<шаг>`.

### S-01 Главное меню — тест `TestS01MainMenu`
1. Новый пользователь: `/start` → E-01 новым сообщением; строка `users` создана, `filters_v` = 1.
2. Повторный `/start` с выбранными фильтрами → E-01; фильтры и `filters_v` не изменились.
3. `m` с любого экрана → E-01 правкой сообщения; записей нет.

### S-02 Поиск и возврат в меню — тест `TestS02Search`
1. E-01 «🔎 Найти забег» → E-02.
2. E-02 «⬅️ Назад» → E-01.

### S-03 Дата — тест `TestS03Date`
1. E-02 «📅 Дата» → E-03; 2. «30 дней» → E-02 с «Дата: 30 дней», `filters_v` +1; 3. E-03 «⬅️ Назад» → E-02 без записи фильтров.

### S-04 Город из списка — тест `TestS04City`
1. E-02 «📍 Город» → E-04; 2. город → E-02 с городом; 3. «Все города» → E-02; 4. «⬅️ Назад» → E-02.

### S-05 Город текстом — тест `TestS05CityText`
1. «Москва» → E-02 новым сообщением с городом; 2. «Моск» → E-08 «не найден» с подсказкой «Москва (n)» (P8); 3. подсказка → E-02 с Москвой; 4. «Атлантида» → E-08 без подсказок, с «Выбрать из списка»; 5. `/foo` → «Нажмите /start, чтобы найти забег». 6. при «всех странах» «Москва» → «Сначала выберите страну» с «🌍 Страна» и «⬅️ Назад», фильтры не изменились, «⬅️ Назад» → E-02 (эталон `s05_needs_country`); 7. «!!!» → «Не понял название города…» с «📍 Выбрать из списка» и «⬅️ Назад», версия в кнопках текущая, фильтры не изменились (эталон `s05_unclear`).

### S-07 Тип — тест `TestS07Type`
1. «🏃 Тип» → E-06 только встречающиеся типы; 2. тип → E-02; 3. «Любой» → E-02.

1. Каталог из двух стран: E-02 со строкой и кнопкой страны; 2. «🌍 Страна» → E-07; 3. «Беларусь» → E-02 с Беларусью; 4. «Все страны» → E-02, город недоступен (как `b165c10`).

### S-09 Список — тест `TestS09List`

### S-13 Сброс с подтверждением — тест `TestS13Reset`

E-13 «🔄 Сбросить настройки» → E-14; 2. «⬅️ Назад» → E-13, строка `users` не изменилась; 3. снова E-14 → «✅ Да, сбросить» → E-13 со значениями по умолчанию, `filters_v` +1, уведомление «Настройки сброшены»; 4. из E-02 «🔄 Сбросить» → E-14 → «⬅️ Назад» → E-02 без записи; 5. → «✅ Да, сбросить» → E-02 по умолчанию.

### S-14 Устаревшая кнопка фильтра (P1) — тест `TestS14StaleFilter`
1. Пользователь сменил фильтр (версия `N` → `N+1`); 2. нажатие кнопки изменения фильтра из старого сообщения (`…:v<N>`) → уведомление «Кнопка устарела — нажмите /start», сообщение не изменено, `users` и `events` равны снимку; 3. то же для кнопки формата `b165c10` без версии (`f:b:1`) и старого `f:x`; 4. устаревшее «✅ Да, сбросить» (`s:y:…:v<N>`) — то же.

### S-15 Устаревшая навигация, совместимость (P2) — тест `TestS15StaleNavigation`
1. `f:s` без версии → E-02 по текущим фильтрам с новыми кнопками; `users` не изменился (включая `last_seen_at`); 2. `p:2:v<старая>` → E-09 страница 1 и «Фильтры изменились — показываю актуальную выдачу», без записи; 3. `e:<id>:1:v<старая>` → E-10, без записи; 4. `s:o:v<старая>` → E-13, без записи; 5. кнопка от пользователя, которого нет в `users`, → экран по умолчанию, строка не создана.

### S-16 Неизвестная кнопка — тест `TestS16Unknown`
1. `zzz`, `f:`, `f:z`, `p:0:v1`, строка длиннее 64 байт, неизвестный префикс → уведомление «Кнопка устарела — нажмите /start», сообщение не изменено, без panic, один ответ, `users` и `events` без изменений.

### S-17 Внутренняя ошибка (P3) — тест `TestS17InternalError`
1. Обработчик паникует → уведомление «Что-то пошло не так, попробуйте ещё раз» (не пустое, не «устарела»), процесс жив, лог `callback internal error`; 2. ошибка БД (закрытый пул) → то же уведомление; 3. устаревшая кнопка в том же тесте → «устарела» и лог `callback stale`.
