## Проверка экранов

| Option | Description | Selected |
|--------|-------------|----------|
| Текстовые снимки из тестов | экраны на фейковом Bot API, эталоны в репозитории | ✓ |
| Отдельный dev-бот | новый токен, меняет D-02 Phase 4 | только после анализа изоляции |
| Только после выката | экраны видны лишь в production | |

**User's choice:** «обязательны текстовые сценарии, тесты и снимки ожидаемых сообщений/клавиатур. Отдельный dev-бот допускается только после анализа изоляции, отдельного токена и отсутствия влияния на production. Не изменять D-02 автоматически.»
**Notes:** дополнительно — не обновлять эталонные снимки автоматически; не вызывать Telegram API в локальных тестах.

## Объём UX

| Option | Description | Selected |
|--------|-------------|----------|
| Полный пользовательский путь | меню, навигация, назад, карточка, фильтры, профиль | ✓ |
| Админские экраны | `/dupes`, `/runs`, алерты | нет, без обоснованной зависимости |
| Профиль (а): «Мои настройки» на существующих данных | без новых полей и миграций | ✓ |
| Профиль (б): новые настройки | требует изменения ROADMAP | |
| Сортировка `/dupes` в Phase 8 | перенесена из Phase 7 | нет — deferred |

**User's choice:** профиль — вариант А; «Сброс настроек — явное действие с тестовым покрытием»; сортировку `/dupes` — в отложенные, вне Phase 8.

## Старые кнопки

| Option | Description | Selected |
|--------|-------------|----------|
| Версия в `f:` | старые кнопки фильтров однократно устаревают | ✓ |
| `f:` без версии | старая кнопка меняет текущие фильтры | |

**User's choice:** «Добавить версию состояния в callback `f:`… Проверять версию до изменения данных. Неизвестные и устаревшие callback не должны изменять users или events.»
**Notes:** «Разделять обработку устаревшего callback и внутренней ошибки.»

## Контракт и приёмка

**User's choice:** сценарии по шагам с точными текстами, кнопками, переходами и ожидаемыми результатами; критерии приёмки и автотесты; отдельно локальная UX-приёмка и production-приёмка. `setMyCommands` — production-эффект.

## Зависимость от Phase 6

**User's choice:** Phase 6 не блокирует аудит, локальное планирование и (после утверждения контракта) локальную реализацию; блокирует production-релиз до выполнения требований Phase 6 и отдельного разрешения.
