<decisions>
## Implementation Decisions

### Уже зафиксировано раньше (не пересматривать)
- Phase 4 (04-CONTEXT.md): экран-сводка фильтров без пошагового мастера (D-10), список по 5 событий с кнопками «1…5» (D-11), корзины дистанций (D-08), типы — только встречающиеся (D-09), пустая выдача с «Снять …» (D-12), `/start` сохраняет фильтры (D-17); `callback_data` ≤ 64 байт, роутинг по префиксу, `answerCallbackQuery` на каждый callback, листание `editMessageText`; один production-бот (D-02).
- BOT-08: о пользователе хранятся только `tg_id`, `filters`, `filters_v` и метки времени.
- ROADMAP: `/stats`, `/broadcast`, избранное и подписки в фазу не входят.

### Аудит
- **D-01:** Исходная реализация для аудита — коммит `b165c10` (HEAD `main` = `origin/main` на 2026-10-03; включает изменения `internal/bot` Phase 7 — строку would_auto в `/dupes`). Прежняя отметка `6d9efa3` в ROADMAP заменена.

### Проверка экранов
- **D-02:** Обязательны текстовые сценарии, автотесты на фейковом Bot API и эталонные снимки ожидаемых сообщений и клавиатур (текст + `callback_data` каждой кнопки). Локальные тесты не вызывают Telegram API.
- **D-03:** Эталонные снимки не обновляются автоматически: несовпадение — падение теста; эталон меняется только правкой файла вместе с изменением контракта.
- **D-04:** Отдельный dev-бот допускается только после анализа изоляции, отдельного токена и отсутствия влияния на production; до этого его нет. D-02 Phase 4 (один бот) автоматически не меняется.

### Объём UX
- **D-05:** Полный пользовательский путь: главное меню, навигация, возврат назад, карточка события, фильтры, профиль.
- **D-06:** Профиль — экран «Мои настройки» только на существующих данных (`users.filters`: страна, город, даты, дистанции, тип) — без новых пользовательских полей и миграций. Сброс настроек — явное действие (кнопка с понятной подписью) с тестовым покрытием.
- **D-07:** `/dupes`, `/runs` и алерты в этой фазе не перерабатываются, если отдельная зависимость не будет обоснована (и согласована владельцем). Сортировка `/dupes` по оценке — вне Phase 8 (deferred).

### Устаревшие и неизвестные callback
- **D-08:** В callback `f:` добавляется версия состояния фильтров (`filters_v`, как уже у `p:` и `e:`). Версия проверяется до изменения данных — в той же операции, что и изменение (без окна между проверкой и записью). Старые кнопки фильтров без версии или с чужой версией — устаревшие. — **Reversibility:** costly — после выката все кнопки фильтров в уже отправленных сообщениях станут устаревшими однократно; откат формата снова сделает устаревшими новые кнопки.
- **D-09:** Обратная совместимость — там, где безопасно: старые callback, не меняющие данных, могут продолжать работать; меняющие данные — только с совпадающей версией.
- **D-10:** Устаревшие и неизвестные callback обрабатываются без panic и отвечают понятным сообщением с предложением выполнить `/start`; не меняют `users` и `events` (проверяется тестом: состояние до и после нажатия совпадает).
- **D-11:** Устаревший callback и внутренняя ошибка обрабатываются раздельно: разные сообщения пользователю и разные строки лога (сейчас при panic обработчика ответ уходит без текста, `internal/bot/bot.go` `cb`).

### Контракт и приёмка
- **D-12:** Контракт — сценарии по шагам: исходный экран, действие, точный текст ответа, кнопки с подписями и `callback_data`, переход, ожидаемый результат (включая неизменность данных там, где это требуется). Контракт утверждает владелец до изменения кода (UX-01). Каждый шаг контракта покрыт автотестом; к контракту — критерии приёмки.
- **D-13:** Приёмка в два этапа:
  - **локальная UX-приёмка** — все тесты сценариев и сверка со снимками проходят, владелец просмотрел снимки по чек-листу;
  - **production-приёмка** — владелец проходит чек-лист в Telegram после выката (UX-03).
- **D-14:** `setMyCommands` (меню команд Telegram) и любые вызовы, меняющие состояние production-бота, считаются production-эффектом: только с выкатом по отдельному разрешению; в локальных тестах — только через фейковый Bot API.

### Зависимость от Phase 6
- **D-15:** Phase 6 не блокирует аудит, контракт и — после утверждения контракта — локальную реализацию и локальную приёмку. Production-приёмка и релиз UX не считаются завершёнными без выполнения требований Phase 6: RESTORE GATE (06-05), актуальный пакет на VPS (повторный `ship.sh` после 07-05), выкат — каждое по отдельному разрешению владельца.

### Requirements
- **D-16:** UX-01…03 приняты (Pending) в согласованном объёме: UX-01 — контракт (D-12), включая главное меню и «Мои настройки» как часть навигации и фильтров; UX-02 — реализация по контракту и D-08…D-11 для устаревших кнопок; UX-03 — production-приёмка (D-13), локальная приёмка — условие перед ней.

### Claude's Discretion
- Формат эталонных снимков и функция сверки (каталог `internal/bot/testdata/`).
- Какие старые callback без изменения данных остаются совместимыми (D-09) — с обоснованием в контракте.
- Тексты внутренней ошибки и устаревшей кнопки — предложение в контракте, утверждает владелец.

## Existing Code Insights

### Reusable Assets
- `internal/bot/ux_test.go` — тесты экранов на фейковом Bot API с точными текстами и `callback_data` (`TestStartScreen`, `TestSearchScreenStructure`, `TestSubmenuBack`, `TestEmptyScreenHints`, `TestCardStructure`) — основа снимков аудита
- `internal/bot/callback.go` — `parseCallback`/`encode`: проверка длины ≤ 64 байт и обратного разбора; `p:` и `e:` уже несут версию `v<filters_v>`
- `internal/store/users.go` `UpdateFilters` — атомарное изменение фильтров, `filters_v` растёт только при реальном изменении
- `internal/bot/bot.go` — `recoverMW` (panic не роняет процесс), `cb` (ровно один `answerCallbackQuery`), `onDefault` (неизвестный callback → `staleNotice`)

### Established Patterns
- Экран = `screen{text, kb}`; навигация `⬅️ Назад` / `⬅️ К фильтрам` / `⬅️ К списку`
- Устаревшая выдача `p:`/`e:` по версии → `staleNotice` или «Фильтры изменились — показываю актуальную выдачу»
- HTML parse mode, экранирование пользовательского ввода (`html.EscapeString`)

### Integration Points
- `f:` callback сейчас без версии (`f:<вид>[:значение]`) — старая кнопка меняет текущие фильтры (D-08 это закрывает)
- При panic в `fn` callback ответ уходит без текста (D-11)
- Главное меню — `/start` (`filters.go`, «КАТАЛОГ ЗАБЕГОВ» с одной кнопкой «Найти забег»); экрана настроек нет
