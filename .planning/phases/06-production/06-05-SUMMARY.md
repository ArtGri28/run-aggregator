## Задача 1 — `deploy/restore-check.sh` и сквозной локальный путь

- Вызов: `deploy/restore-check.sh <файл.dump.age> <файл ключа> '<подпись>'`.
- Порядок: SHA-256 и размер против подписи → отдельный контейнер PostgreSQL без сети (образ сервиса `postgres` из `docker-compose.yml`, данные в tmpfs) → `age -d | pg_restore` одним конвейером → строка `counters_sql` против `counts` подписи.
- Контракт выхода: `RESTORE OK counters=match migration=<n>` — код 0; `RESTORE FAIL reason=sha|decrypt|restore|counters` — код 1, подтверждённый отказ копии или восстановления; `STOP: <причина>` в stderr — код 2, проверку нельзя выполнить достоверно (в том числе подтверждённый сбой окружения во время восстановления или запроса счётчиков: код `docker exec` от 125, контейнер остановился, `pg_restore` сообщил о нехватке места, памяти или потере соединения, `psql` не подключился); прочие ошибки `pg_restore` — `reason=restore`; прерывание сигналом — `INTERRUPTED signal=<имя>` в stderr, коды 130 (INT), 143 (TERM), 129 (HUP), без строк `RESTORE`.
- Образ не скачивается: нужен локальный, запуск с `--pull never`.
- Сообщения `age`, `pg_restore` и `psql` не печатаются; вместо них строка `detail stage=age|pg_restore|counters exit=<код>`, для `pg_restore` — ещё `age_exit=<код> kind=archive-version|archive-format|data|query|other` и `table=<имя>` для `data`.
- Удаляется только контейнер, запущенный этим процессом; занятое имя — `STOP` без удаления.

Сигнатура `counters_sql` (06-02, `deploy/vps/backup-lib.sh`): функция без аргументов, печатает в stdout текст одного SQL-запроса, к БД не обращается. Допущение плана подтверждено.

## Оставшиеся ограничения

- Гонка при прерывании во время `docker run`: контейнер может появиться после очистки и остаться.
- SIGKILL и падение Docker очистку не запускают: контейнер с расшифрованными данными остаётся до ручного удаления.
- `kind=` определяется по английским текстам `pg_restore`; другая версия или локаль образа даст `kind=other` (причина `reason=restore` при этом верна).
- Сбой окружения распознаётся эвристикой: дамп, который сам роняет PostgreSQL, даст `STOP`, а не `RESTORE FAIL`; значение в данных со встроенным переводом строки, имитирующее строку `pg_restore:` с фразой о нехватке места, тоже даст `STOP`; при другой локали или версии образа текстовые признаки не сработают и нехватка места без остановки контейнера станет `reason=restore`. Ложного `RESTORE OK` эти случаи не дают.
- При `kind=other` текст ошибки не виден; для разбора нужен ручной повтор `age -d | pg_restore`.
- Правило кода 141 ловится тестом только если `age` не успел дописать поток (на 50 МБ ловилось каждый раз).
- Сверка с подписью не обнаружит согласованную подмену файла и подписи владельцем токена бота бэкапов (принятый риск T-06-43).
