# 23-03: источник reg.place (публичные страницы)

**Основа:**
- `23-CONTEXT.md`: D-04, D-05, Q-3 — пока reg.place не ответил о программном интерфейсе, данные берутся только с публичных страниц, `api.reg.place` не используется;
- Q-4 — reg.place подключается вторым;
- проверка сайтов 2026-10-20: образцы списка (пять страниц) и одной страницы события.

Экраны, эталоны и схема не меняются, миграций нет.

## Что на страницах

- **Список `/events?page=N`.** Пять страниц по 12 карточек, всего 56 будущих событий.
  - Карточка `article.b-event-card` содержит:
    - slug из ссылки `/events/<slug>`;
    - метки видов спорта: «Бег», «Велогонка», «Плавание», «Лыжи», «Триатлон», «Кемп», «Другой вид», «Дети (до 17 лет)»…;
    - название;
    - дату без года («24 октября», «30 октября — 1 ноября»);
    - город;
    - ссылку «/registration» или надпись «Регистрация закрыта».
  - Класс карточки: `--registration-open` или `--registration-closed`.
- **Страница события `/events/<slug>`.**
  - Дата с годом (`24.10.2026`) и адрес строкой: «Спас-Каменка, Московская обл, г Дмитров, деревня Спас-Каменка».
  - Карточки дистанций `race-card`: «Дистанция 21,0 км», «430,0 м».
  - Ссылка «Сайт соревнований».
  - Блок организатора: ФИО, телефон, ИНН — **не читается и не сохраняется**.

## Задачи

1. **Образцы.**
   - Из сохранённых 2026-10-20 страниц: список, страница 1 (страницы 2–5 — для подсчёта), и страница события `spaskamenka2026`.
   - Из файлов убираются скрипты, стили, картинки, формы, блок организатора, цены и остатки слотов.
   - Дополнительно — не больше 3 страниц событий для крайних случаев: многодневный старт (Железноводск), заплыв, велогонка. Только чтение, пауза не меньше 10 с, честный User-Agent проекта.
   - README образцов — таблица фактов по каждой карточке. Эталон собирается по таблице, а не по выводу разбора.
2. **Адаптер `regplace`.**
   - **Прогон:**
     - страницы списка по ссылке «следующая», не больше 10 страниц;
     - затем страница каждого отобранного события;
     - пауза хоста 10 с, около 50 запросов, примерно 8–9 минут за прогон;
     - ошибка любой страницы — ошибка прогона, неполный набор не возвращается.
   - **Отбор по меткам:**
     - вид спорта определяет первая подходящая метка в порядке: «Лыжи», «Лыжероллеры», «Плавание», «Велогонка», «Бег», «Триатлон», «Акватлон», «Дуатлон»;
     - «Триатлон», «Акватлон» и «Дуатлон» — мультиспорт: он собирается, но выключен в справочнике и не показывается;
     - карточки без таких меток (шахматы, борьба, «Кемп», «Другой вид») пропускаются без запроса страницы;
     - онлайн-старты — «онлайн» или «Zwift» в названии — тоже пропускаются.
   - **Поля записи:**
     - external_id — slug;
     - URL — `https://reg.place/events/<slug>` (D-05);
     - RegistrationURL — `…/registration`, только у карточки с открытой регистрацией;
     - Title — с карточки;
     - Date — с даты страницы события (`dd.mm.yyyy`), EndDate — из диапазона карточки с годом страницы, а для «31 декабря — 2 января» — следующий год;
     - City — с карточки;
     - Region — первая часть адреса, которую распознаёт `normalize.ClassifyRegion` («Московская обл»);
     - Country — RU, а BY, если в адресе есть «Беларусь»;
     - Distances — дистанции из `race-card` через запятую; карточки дистанций без километров и метров (время, «эстафета») не дают дистанции;
     - TypeLabel — по виду спорта, как у остальных источников: плавание — «открытая вода», если в названии нет «бассейн»; велогонка — по словам «МТБ», «кросс-кантри», «гревел», «шоссе»; лыжи — «Лыжные гонки».
   - **Не берутся:** описание, цены, слоты, организатор, «Сайт соревнований», страницы `/heats`, `/registration`, личный кабинет.
3. **Регистрация источника.**
   - Источник добавляется в `newSources` с обычным загрузчиком.
   - Подпись в карточке — «Reg.place».
   - Комментарий в `newSources`: «с разрешения владельца сайта, только публичные страницы».
4. **Тесты.**
   - Разбор списка и страницы события против эталонов.
   - Отбор по меткам и онлайн-стартов.
   - Год и дата окончания на стыке лет.
   - Дистанции в метрах и километрах с запятой.
   - Регион из адреса, Беларусь.
   - Регистрация закрыта — нет ссылки на регистрацию.
   - Ошибка страницы события — ошибка прогона.
   - Не больше 10 страниц списка.
   - Все записи проходят `Prepare`.
5. **`deploy/README.md`:** раздел «Phase 23: reg.place».
   - Первый прогон — `suspect`, его принимает владелец.
   - Ожидается около 40 записей, из них около 35 — пары-кандидаты с ПроБЕГом, Swimcup и SwimRocket в `/dupes`; новых около 8.
   - Прогон длится 8–9 минут.

## Проверки

`go vet ./...`, `gofmt -l`, полный прогон тестов: 573 прежних PASS, 0 FAIL, 0 SKIP, плюс новые. Эталоны экранов не меняются.

## Риски

- **Много пар-кандидатов.** Около 35 пар в `/dupes` — большая ручная работа для владельца. Автослияние выключено и не включается.
- **Неполный каталог.** Похоже, в каталоге reg.place только события с открытой или недавно закрытой регистрацией. Если регистрация закрылась давно, старт может исчезнуть из списка и через несколько прогонов будет помечен пропавшим. Это общее правило конвейера, у других источников так же.
- **Нагрузка.** Около 50 запросов за прогон. Если reg.place назовёт другой темп или откроет список в API, адаптер переделывается отдельным планом.

## Не входит

`api.reg.place` (до ответа reg.place), выкат (23-04), включение мультиспорта, хранение стиля, описание и цены.
