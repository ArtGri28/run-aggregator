# Phase 3 Plan 06: первый реальный прогон и решение по fallback RU — Summary

**Первый реальный прогон Марафонца в dev-БД дал `suspect` (D-05) со снимком 133 записей; владелец по санити-отчёту подтвердил fallback `RU` (confirm). Базовый уровень не принят — это план 03-07.**

## Задача 1: первый прогон (владелец)

- Прогоны 1–4 — `failed`, запрос до сайта не начинался: 1 — `context canceled` (прерван), 2–4 — `lookup marathonec.ru: i/o timeout`. Причина — DNS-сервер роутера `192.168.0.1` не отвечает на запросы (таймаут и для `ya.ru`); после смены резолвера en0 на `1.1.1.1/1.0.0.1` (выдан автоматически, сетевые настройки Mac вручную не менялись) имя разрешается. Код worker/fetch не менялся.
- Прогон 5 (2026-09-29 19:23 UTC): `suspect`, причина «первый прогон источника — требуется принятие; доля вне каталога (out_of_scope): 100.0 % (133 из 133) выше порога 20.0 %» — вторая часть ожидаема при политике `NoFallback` до решения D-07. `fetched=133 parsed=133`, снимок сохранён, `accepted_at` пуст.
- `source_events` = 0, `events` = 0 (suspect ничего не применяет).
- Сырой ответ `data/raw/marathonec/5-0.html` (598490 Б) и `.meta.json`, каталог 0700, игнорируется git.
- Санити-отчёт `03-SANITY-REPORT.md`: 133 строки, 43 уникальные области, 43 в перечне РФ, НЕТ в перечне 0, иностранных 0, область пуста 0, несколько областей 2 («Вся Россия» с 27 областями; «Краснодарский край + Республика Адыгея»). E-mail в отчёте нет.
- Проверка FIRST RUN OK выполнена по частям через `docker exec aggregator-dev-postgres-1 psql` (compose требует переменных из `.env`, который исполнитель не читает): все условия выполнены.

## Задача 2: решение владельца

Дословно: «По результатам первого реального прогона разрешаю RU fallback для Марафонца. Основание: 133 события проверены; 43 уникальные области; 43/43 входят в перечень РФ; иностранных областей 0; пустых областей 0. … baseline пока НЕ принимать.»

## Дополнительная проверка по запросу владельца: несколько дистанций

Все дистанции события сохраняются отдельными строками `event_distances` (`store.replaceDistances` вставляет каждую `event.Distance`), а не только максимальная. Проверено на тестовой БД прогоном фикстуры (`TestRunFixture`, принятие + повторный прогон): 133 события, 448 строк `event_distances`, у 132 событий есть хотя бы одна дистанция (у «Часового забега» только «1 час» — не дистанция), у 114 событий больше одной; максимум 10 («Т-Банк Rosa Wild Fest»: 6,3; 12; 13; 20; 35; 40; 45; 80; 115; 180 км). Совпадает с `prepared.golden.json` (448 дистанций, 114 событий с несколькими).
