## 1. Принципы

Раздел 1 контракта Phase 8 (один возврат «⬅️ Назад», экран меняется на месте, данные меняет только явное действие с актуальной кнопкой, одно уведомление на нажатие) действует для всех экранов этой фазы без копирования. Дополнения фазы:

1. **Добровольность (D-01).** Анкету можно пропустить целиком и любой вопрос по отдельности; любой ответ можно изменить через `/profile`; отказ ничего не ограничивает: поиск, список, карточка и настройки работают так же, как у пользователя без анкеты (PRF-03).
2. **Удаления профиля у пользователя нет (D-02).** Ни команды, ни кнопки, ни подтверждения, ни «очистить все ответы». Технические действия с `users` и сброс настроек поиска не меняются и профиль не затрагивают.
3. **У поля нет кнопки отказа от ответа (D-03).** Ответ либо выбран, либо поле пустое с момента пропуска. Пол, возраст и страну после выбора можно только заменить; у видов спорта можно снять все отметки.
4. **Профиль независим от настроек поиска (D-08, PRF-06).** Код профиля не пишет и не читает `users.filters`, код фильтров не читает `user_profiles`; версии раздельные (`profile_v` и `filters_v`); автоподстановки города нет. Код вида спорта `ocr` и тип события `obstacle` — разные справочники и не связываются. Кнопки `u:`, команда `/profile` и ответ на город текстом не пишут в `users`, включая `last_seen_at` (дополнение А раздела 13); `<N>` в кнопках главного меню берётся чтением версии без записи (дополнение Б).
5. **Что хранится и что обещается (D-11, D-12; редакция 2026-10-06).** Ответы хранятся бессрочно и попадают в резервные копии базы. Тексты экранов ничего не обещают о данных: ни об удалении ответов, ни о том, кто их видит и для чего они используются.
6. **Логи без персональных данных (PRF-09).** В лог не попадают текст города, значения полей, коды видов спорта и `tg_id`; логируется только вид события (`callback stale prefix=u`, `callback internal error prefix=u`, ошибки).

## 2. Дерево навигации

```
/start
├── строки профиля нет → O-1 Предложение (вместо главного меню; строка профиля создаётся до отправки)
│   ├── «📝 Заполнить анкету» → O-2 Вопрос 1 «Пол»
│   │     → O-3 Вопрос 2 «Возраст»
│   │     → O-4 Вопрос 3 «Где вы живёте?»: экран страны → экран города (кнопка или текст → «Дальше» / «Изменить»)
│   │     → O-5 Вопрос 4 «Виды спорта» → «✅ Готово» → O-6 Главное меню + «Спасибо! Анкета сохранена»
│   │   (на каждом вопросе: «Пропустить вопрос» → следующий; «⬅️ Назад» → предыдущий; с вопроса 1 → Главное меню)
│   └── «Пропустить» → Главное меню
└── строка профиля есть (любой статус) → Главное меню

Главное меню
├── 🔎 Найти забег / ⚙️ Мои настройки → без изменений (разделы 2–4 контракта Phase 8)
└── 👤 Мой профиль → P-1 «Мой профиль» (/profile — тот же экран новым сообщением)
      ├── 🚻 Пол / 🎂 Возраст / 🏅 Спорт → P-2 «Правка поля» → выбор → P-1  («⬅️ Назад» → P-1)
      ├── 🏠 Где живу → P-2 страна → экран города (кнопка → P-1; текст → «Дальше» → P-1 / «Изменить»)
      │                   «⬅️ Назад» с города → страна; «⬅️ Назад» со страны → P-1
      └── ⬅️ Назад → Главное меню
```

## 3. Формат callback

Новый префикс `u:` (D-14). Версия `v<P>` — всегда последнее поле; режим `w` — анкета, `e` — редактирование.

| Вид | Формат | Меняет данные | Версия |
|---|---|---|---|
| профиль | `u:o` | нет | не нужна (экран читает строку без записи) |
| начать анкету | `u:b:v<P>` | да (статус) | да |
| пропустить анкету | `u:n:v<P>` | да (статус) | да |
| показать вопрос | `u:a:<g\|a\|k\|c\|s>:<w\|e>:v<P>` | нет ответов; экран города ставит отметку ожидания (раздел 7), остальные снимают её | да |
| сохранить ответ | `u:s:<поле>:<значение>:<w\|e>:v<P>` | да | да |
| готово | `u:z:v<P>` | да (статус) | да |

Поля и допустимые значения (всё иное кодек отвергает — PRF-04):

| Поле | Значения | Подписи |
|---|---|---|
| `g` пол | `m`, `f` | Мужской, Женский |
| `a` возраст | `0`, `1`, `2`, `3`, `4`, `5` | До 18, 18–24, 25–34, 35–44, 45–54, 55+ |
| `k` страна | `RU`, `BY`, `KZ`, `ZZ` | 🇷🇺 Россия, 🇧🇾 Беларусь, 🇰🇿 Казахстан, 🌍 Другая страна |
| `c` город | ключ города по правилу ключей каталога (`[a-z0-9-]+`), не длиннее 49 байт | название города из каталога выбранной страны |
| `s` вид спорта | `run`, `trail`, `ocr`, `bike`, `swim`, `ski`, `tri`, `row` | 🏃 Бег, 🏔 Трейлраннинг, 🧗 OCR · гонки с препятствиями, 🚴 Велоспорт, 🏊 Плавание, ⛷ Лыжные гонки, 🏅 Триатлон, 🚣 Гребля |

- `u:s:k:<страна>` сохраняет страну; если страна изменилась, город и ключ города очищаются; затем показывается экран города.
- `u:s:c:<ключ>` сохраняет город под названием каталога выбранной страны; ключа нет в каталоге или страна не выбрана — устаревшая кнопка (раздел 5).
- `u:s:s:<код>` переключает вид спорта (есть — снимает, нет — добавляет); экран остаётся на месте.
- Длина ≤ 64 байт проверяется при создании кнопки (`encode`, как в разделе 3 контракта Phase 8): кнопка, которая не помещается, не показывается. Для города: `u:s:c:` (6) + ключ + `:w:v` (4) + цифры `P`; с ключом в 49 байт кнопка помещается при `P` до 99999, при большей версии кнопка такого города не показывается, город вводится текстом; общий предел ключа — 64 − 10 − число цифр `P`. Ключ длиннее 49 байт в кнопке не показывается никогда.
- Профиль не использует `stamp`: кнопки профиля получают `V: <P>` при построении экрана.

## 4. Экраны

Метод: «новое сообщение» — `sendMessage`, «правка» — `editMessageText`. Каждое нажатие кнопки отвечает одним `answerCallbackQuery` (дополнение Г). Версия `<P>` в кнопках экрана — версия профиля после выполненного действия.

### O-1 Предложение (`/start` — новое сообщение)
Приходит вместо главного меню при первом `/start` нового пользователя и при следующем `/start` действующего пользователя без строки профиля (D-05). Строка профиля (`not_started`, `offered_at`) создаётся до отправки (D-06).
```
🏁 <b>Где старт?</b>
Соревнования по бегу в разных городах

Можно ответить на 4 коротких вопроса о себе. Анкета добровольная: любой вопрос можно пропустить, а ответы — изменить в /profile. Поиск работает и без неё.
---
[📝 Заполнить анкету] → u:b:v<P>
[Пропустить] → u:n:v<P>
```
«Пропустить» → главное меню правкой сообщения (E-01), статус `skipped`.

### O-2 Вопрос 1 из 4 «Ваш пол»
Режим `w` (правка):
```
<b>Вопрос 1 из 4</b>
Ваш пол
---
[Мужской] → u:s:g:m:w:v<P> | [Женский] → u:s:g:f:w:v<P>
[Пропустить вопрос] → u:a:a:w:v<P>
[⬅️ Назад] → m
```
Режим `e` (P-2, правка):
```
<b>Ваш пол</b>
---
[Мужской] → u:s:g:m:e:v<P> | [Женский] → u:s:g:f:e:v<P>
[⬅️ Назад] → u:o
```
Сохранённое значение — с «✓ » (`[✓ Мужской]`) в обоих режимах. Выбор в `w` сохраняет и показывает O-3; в `e` сохраняет и показывает P-1.

### O-3 Вопрос 2 из 4 «Ваш возраст»
Режим `w`:
```
<b>Вопрос 2 из 4</b>
Ваш возраст
---
[До 18] → u:s:a:0:w:v<P> | [18–24] → u:s:a:1:w:v<P>
[25–34] → u:s:a:2:w:v<P> | [35–44] → u:s:a:3:w:v<P>
[45–54] → u:s:a:4:w:v<P> | [55+] → u:s:a:5:w:v<P>
[Пропустить вопрос] → u:a:k:w:v<P>
[⬅️ Назад] → u:a:g:w:v<P>
```
Режим `e`: текст `<b>Ваш возраст</b>`, кнопки выбора с `:e:`, последняя строка `[⬅️ Назад] → u:o`, без «Пропустить вопрос». Выбор в `w` сохраняет и показывает экран страны O-4; в `e` — P-1.

### O-4 Вопрос 3 из 4 «Где вы живёте?»
Два экрана в одном сообщении (правка): страна, затем город.

**Экран страны, режим `w`:**
```
<b>Вопрос 3 из 4</b>
Где вы живёте?
---
[🇷🇺 Россия] → u:s:k:RU:w:v<P> | [🇧🇾 Беларусь] → u:s:k:BY:w:v<P>
[🇰🇿 Казахстан] → u:s:k:KZ:w:v<P> | [🌍 Другая страна] → u:s:k:ZZ:w:v<P>
[Пропустить вопрос] → u:a:s:w:v<P>
[⬅️ Назад] → u:a:a:w:v<P>
```
**Экран страны, режим `e`:** текст `<b>Где вы живёте?</b>`, кнопки с `:e:`, последняя строка `[⬅️ Назад] → u:o`. Текущая страна — с «✓ ». Выбор страны (в обоих режимах) сохраняет её и показывает экран города; выбор той же страны город не меняет.

**Экран города, режим `w`** (до 10 городов выбранной страны из каталога, по две в ряд, подпись — название без числа событий):
```
<b>Вопрос 3 из 4</b>
Страна: 🇧🇾 Беларусь

Выберите город или напишите его название сообщением
---
[Минск] → u:s:c:minsk:w:v<P> | [Гомель] → u:s:c:gomel:w:v<P>
[Пропустить вопрос] → u:a:s:w:v<P>
[⬅️ Назад] → u:a:k:w:v<P>
```
**Экран города, режим `e`:** текст `<b>Где вы живёте?</b>` (далее строки «Страна: …» и «Выберите город…» те же), кнопки городов с `:e:`, последняя строка `[⬅️ Назад] → u:a:k:e:v<P>`; «Пропустить вопрос» нет.

Для «🌍 Другая страна» и для страны, у которой в каталоге нет городов, кнопок городов нет, последняя строка текста — «Напишите название города сообщением» (вместо «Выберите город или напишите его название сообщением»). Страна в строке «Страна: …» для `ZZ` — «🌍 Другая страна».

Показ экрана города актуальной кнопкой ставит отметку ожидания города на 10 минут (раздел 7). Выбор города кнопкой сохраняет его (название и ключ каталога), снимает отметку и показывает O-5 (`w`) или P-1 (`e`).

**Ответ на текст — город записан** (новое сообщение; текст города экранируется):
```
🏠 Город проживания: {город}
---
[Дальше] → u:a:s:w:v<P> | [Изменить] → u:a:c:w:v<P>      (режим w)
[Дальше] → u:o | [Изменить] → u:a:c:e:v<P>               (режим e)
```
«Дальше» — вопрос 4 (`w`) или P-1 (`e`); «Изменить» — экран города того же режима (ставит отметку заново). Исключение из принципа 1: здесь нет «⬅️ Назад» — выход «Дальше» или «Изменить».

### O-5 Вопрос 4 из 4 «Виды спорта»
Режим `w`:
```
<b>Вопрос 4 из 4</b>
Какие виды спорта вам близки? (можно несколько)
---
[🏃 Бег] → u:s:s:run:w:v<P> | [🏔 Трейлраннинг] → u:s:s:trail:w:v<P>
[🧗 OCR · гонки с препятствиями] → u:s:s:ocr:w:v<P> | [🚴 Велоспорт] → u:s:s:bike:w:v<P>
[🏊 Плавание] → u:s:s:swim:w:v<P> | [⛷ Лыжные гонки] → u:s:s:ski:w:v<P>
[🏅 Триатлон] → u:s:s:tri:w:v<P> | [🚣 Гребля] → u:s:s:row:w:v<P>
[✅ Готово] → u:z:v<P>
[⬅️ Назад] → u:a:k:w:v<P>
```
Нажатие вида спорта сразу сохраняет и оставляет экран на месте: «✓ » у выбранных (`[✓ 🏃 Бег]`), версия в кнопках новая. «Пропустить вопрос» нет — его роль у «✅ Готово».
Режим `e` (P-2): текст `<b>Какие виды спорта вам близки? (можно несколько)</b>`, кнопки с `:e:`, **без «✅ Готово»**, последняя строка `[⬅️ Назад] → u:o`. Снять можно все отметки (D-03).

### O-6 Завершение
`u:z` → правка сообщения на главное меню E-01 (с `<N>`), уведомление на кнопку: «Спасибо! Анкета сохранена». Статус `completed`, `completed_at`. «Готово» завершает анкету независимо от того, сколько вопросов заполнено.

### P-1 Мой профиль (`/profile` — новое сообщение; `u:o` — правка)
```
👤 <b>Мой профиль</b>

🚻 Пол: Мужской
🎂 Возраст: 25–34
🏠 Живу: 🇧🇾 Беларусь, Минск
🏅 Спорт: Бег, Велоспорт
---
[🚻 Пол] → u:a:g:e:v<P> | [🎂 Возраст] → u:a:a:e:v<P>
[🏠 Где живу] → u:a:k:e:v<P> | [🏅 Спорт] → u:a:s:e:v<P>
[⬅️ Назад] → m
```
Правила значений:
- пустые: «Пол: не указан», «Возраст: не указан», «Спорт: не указан», «Живу: не указано»;
- спорт — названия без эмодзи через запятую в порядке D-04 (`Бег, Трейлраннинг, OCR · гонки с препятствиями, Велоспорт, Плавание, Лыжные гонки, Триатлон, Гребля`);
- место проживания — «{флаг} {страна}, {город}» или только «{флаг} {страна}»; для `ZZ` — «🌍 Другая страна» (с городом — «🌍 Другая страна, {город}»); город экранируется (`html.EscapeString`);
- нет строки профиля — P-1 с пустыми полями и кнопками версии `v0`, без записи (раздел 5).

### P-2 Редактирование поля
Это экраны вопросов O-2…O-5 в режиме `e` (без «Вопрос N из 4» и «Пропустить вопрос», «✓ » у текущего значения, «⬅️ Назад» → `u:o`). Выбор сохраняет и возвращает в P-1 (для города и вида спорта — как описано выше); «⬅️ Назад» — в P-1 без записи. Изменение сохраняется, если значение другое: `profile_v` и `updated_at` растут только при реальном изменении.

### E-01 (новая редакция) Главное меню
Заменяет E-01 контракта Phase 8 (раздел 13.1): текст прежний, добавляется третья кнопка (D-13).
```
🏁 <b>Где старт?</b>
Соревнования по бегу в разных городах

Собрали беговые старты из разных календарей в одном месте. Выбери город, даты и дистанцию — покажу, куда можно заявиться.
---
[🔎 Найти забег] → f:s:v<N>
[⚙️ Мои настройки] → s:o:v<N>
[👤 Мой профиль] → u:o
```
`/start` при существующей строке профиля (любой статус) показывает это меню; для нового пользователя и для действующего без строки профиля — O-1 (раздел 6).

## 5. Устаревшие кнопки `u:`

Кнопка `u:` **устаревшая**, если её `v<P>` не равна текущей `profile_v` или у пользователя нет строки профиля. Правила раздела 5 контракта Phase 8 сохраняются (одно уведомление, лог `callback stale prefix=u`, без данных пользователя в логе).

| Случай | Что видит пользователь | Запись в БД |
|---|---|---|
| актуальная кнопка | экран по контракту | разрешена только в `user_profiles` (`profile_v` при изменении, `status`, `started_at`, `completed_at`, `updated_at`, отметка ожидания); `users` не пишется |
| устаревшая, изменяющая (`u:b`, `u:n`, `u:s`, `u:z`) — чужая версия | сообщение не меняется; уведомление «Кнопка устарела — нажмите /start» | **никакой** |
| устаревшая, навигационная (`u:a`) — чужая версия | правка сообщения на экран того же поля по текущему состоянию, с кнопками актуальной версии; режим `w` показывается только при статусе `in_progress`, иначе экран поля в режиме `e` | **никакой**; отметка ожидания не ставится и не снимается |
| устаревшая `u:a:c`, а также `u:a:c` при невыбранной стране | экран страны (того же режима по правилу выше) | **никакой** |
| нет строки профиля: `u:o` | P-1 с пустыми полями и кнопками версии `v0` | **никакой** (строка не создаётся) |
| нет строки профиля: `u:a` | экран вопроса (режим `e`) без ответов | **никакой** |
| нет строки профиля: `u:b`, `u:n`, `u:s`, `u:z` | уведомление «Кнопка устарела — нажмите /start» | **никакой** |
| актуальная версия, недопустимый для статуса переход: `u:b` и `u:n` не из `not_started`; `u:z` не из `in_progress` | уведомление «Кнопка устарела — нажмите /start» | **никакой** |
| `u:s:c:<ключ>`: ключа нет в каталоге выбранной страны, либо страна не выбрана | уведомление «Кнопка устарела — нажмите /start» | **никакой** |
| значение вне грамматики (раздел 3: `u:s:g:x:…`, `u:s:a:6:…`, `u:s:s:other:…`, ключ города длиннее 49 байт, `u:z` без версии, неизвестный вид `u:q`) | уведомление «Кнопка устарела — нажмите /start» | **никакой** |
| внутренняя ошибка (ошибка БД, panic обработчика) | сообщение не меняется; уведомление «Что-то пошло не так, попробуйте ещё раз» | транзакция откатывается |

Версия и запись — в одной транзакции под блокировкой строки профиля (между проверкой и изменением нет окна). Кнопки `f:`, `s:`, `p:`, `e:`, `g:`, `m` профиль и отметку ожидания не трогают.

## 6. Состояния анкеты

```
(нет строки) ──первый /start──▶ not_started
not_started ──«Заполнить анкету»──▶ in_progress
not_started ──«Пропустить»──▶ skipped
in_progress ──«Готово» на 4-м вопросе──▶ completed
not_started / skipped ──первый ответ через /profile──▶ in_progress
in_progress ──все 4 поля заполнены через /profile──▶ completed
completed ──изменение ответа──▶ completed (растут profile_v, updated_at)
```

Правила:
- «Все 4 поля заполнены» — пол, возраст, страна и хотя бы один вид спорта (город не нужен).
- В анкете (режим `w`) статус `completed` даёт только «✅ Готово»; при редактировании (режим `e`) — заполнение всех четырёх полей.
- Допустимость по статусу: `u:b` и `u:n` применяются только из `not_started`, `u:z` — только из `in_progress`; иначе кнопка устаревшая (раздел 5).
- Первый ответ из `not_started` или `skipped` (любой режим) переводит в `in_progress`, `started_at` ставится при первом переходе в `in_progress`; `completed_at` — при переходе в `completed`.
- `profile_v` и `updated_at` растут только при реальном изменении ответов или статуса; постановка и снятие отметки ожидания версию не меняют; повторный выбор того же значения не пишет.
- Обратных переходов из `completed` нет (снятие всех видов спорта статус не меняет); `skipped` возникает только из предложения.
- Повторный `/start` при любом статусе — главное меню; предложение O-1 показывается ровно один раз на пользователя: «предложена» = строка профиля создана (D-06), сорвавшаяся отправка предложения повторно его не вызывает.
- Прерывание (`/start`, текст, молчание) оставляет `in_progress`; сохранённые ответы на месте. «Пропустить вопрос» и «⬅️ Назад» — навигация без записи.

## 7. Город текстом

Принимается только при отметке ожидания (D-09, D-10, PRF-08, PRF-09).

- **Отметка** — `awaiting_city_until` (10 минут) и режим экрана (`w` или `e`, колонка `awaiting_city_mode`; схему утверждает 09-02, уточнение 4).
- **Ставится** при показе экрана города актуальной кнопкой: `u:s:k:<страна>`, `u:a:c`, «Изменить».
- **Снимается:** `/start`, `/profile`, любой актуальной кнопкой `u:`, кроме показывающих экран города; сохранением города (кнопкой или текстом); истечением 10 минут. Кнопки `f:`, `s:`, `p:`, `e:`, `g:`, `m` и устаревшие `u:` отметку не трогают (уточнение 10).
- **Текст в окне:** приводится к одной строке (пробелы и переводы строк — один пробел, как в поиске; дополнение Д); длина до 64 символов, не начинается с `/`; иначе прежний ответ «Нажмите /start, чтобы найти забег», ничего не сохраняется, отметка остаётся. Принятый текст сохраняется как город проживания и в поиск **не идёт**; фильтры (`users.filters`, `filters_v`) не меняются, `users` не пишется.
- **Совпадение с каталогом:** текст, совпавший с городом каталога выбранной страны, сохраняется под названием каталога и с его ключом; иначе — как введён, ключ пустой (D-09, обрезка пробелов, ≤ 64 символов).
- **Ответ:** новое сообщение «🏠 Город проживания: {город}» с «Дальше» и «Изменить» (O-4). Город экранируется при выводе; в `callback_data` и в логи не попадает.
- **После истечения окна** текст идёт в поиск как обычно (PRF-08, раздел 14.3 контракта Phase 8).
- **Известное ограничение (D-10):** поисковый запрос, отправленный в это окно, сохранится как город; ответ бота это показывает и даёт «Изменить».

## 8. Сценарии

Каждый шаг — тест `TestSxx<Имя>` на фиктивном Bot API и сверка со снимком; имя эталона — `sxx_<шаг>`. Формула шага: исходный экран → действие → ожидаемый экран; в конце — состояние базы. Во всех сценариях строка `users` и `users.filters` кнопками профиля не изменяются (PRF-06), если не сказано иное.

## 13. Уточнения плана

Договорённости, которых нет в 09-CONTEXT.md `<screens>`; владелец может изменить любое.

1. Анкета (режим `w`): выбор ответа сохраняет и показывает следующий вопрос; «Пропустить вопрос» — следующий вопрос без записи (`u:a` следующего поля); «⬅️ Назад» — предыдущий вопрос без записи, на первом вопросе — главное меню (`m`).
2. Вопрос 3 — два экрана в одном сообщении: страна, затем город. Смена страны очищает город. «⬅️ Назад» с экрана города — экран страны, с экрана страны — вопрос 2.
3. Экран города: кнопки — до 10 городов выбранной страны из каталога, подпись — название без числа событий; для `ZZ` и для страны без городов в каталоге кнопок городов нет, текст экрана — «Напишите название города сообщением».
4. Ответ на город текстом — новое сообщение «🏠 Город проживания: {город}»; «Дальше» — вопрос 4 в анкете и P-1 при редактировании; «Изменить» — экран города. Режим запоминается вместе с отметкой ожидания (дополнение к D-07: колонка `awaiting_city_mode`, схема утверждается в 09-02).
5. Вопрос 4: нажатие вида спорта сразу сохраняет и оставляет на экране, «✓» у выбранных; «✅ Готово» — только в анкете. В редактировании у экрана спорта только «⬅️ Назад» в P-1.
6. P-1: пустые значения — «не указан» (пол, возраст, спорт) и «не указано» (место проживания); спорт — названия через запятую без эмодзи в порядке D-04; место проживания — «флаг страна, город» или только страна; для `ZZ` — «🌍 Другая страна».
7. Статусы — по разделу 6. «Все 4 поля заполнены» = пол, возраст, страна и хотя бы один вид спорта. В анкете статус `completed` даёт только «✅ Готово»; при редактировании — заполнение всех четырёх.
8. Допустимость по статусу: `u:b` и `u:n` применяются только из `not_started`, `u:z` — только из `in_progress`; иначе кнопка считается устаревшей.
9. Нет строки профиля: `u:o` и `/profile` показывают P-1 с пустыми полями и кнопками версии `v0`, без записи; навигационная `u:a` — экран вопроса без записи; изменяющая — «Кнопка устарела — нажмите /start».
10. Отметка ожидания города: ставится на 10 минут при показе экрана города актуальной кнопкой; снимают `/start`, `/profile`, любая актуальная кнопка `u:` (кроме показывающих экран города), сохранение города кнопкой или текстом, истечение времени. Кнопки `f:`, `s:`, `p:`, `e:`, `g:`, `m` и устаревшие `u:` её не трогают. Устаревшая `u:a:c` и `u:a:c` без выбранной страны показывают экран страны.
11. Текст в окне ожидания: одна строка, до 64 символов, не начинается с `/` — иначе прежний ответ «Нажмите /start, чтобы найти забег», ничего не сохраняется. Текст, совпавший с городом каталога выбранной страны, сохраняется с названием и ключом каталога; иначе — как введён, ключ пустой (D-09).
12. Длина кнопки города: `u:s:c:<ключ>:<режим>:v<P>` с ключом 49 байт помещается в 64 байта при версии до 99999; при большей версии кнопка такого города не показывается, город вводится текстом.
13. Тесты и эталоны Phase 8 под D-05: эталоны `start` и `s01_start` становятся экраном O-1; тесты, предмет которых — главное меню или приветствие, получают его вторым `/start`.

**Дополнения к уточнениям, внесённые при составлении контракта** (в `<context>` плана их нет; на утверждение владельца):

- **А.** Кнопки `u:`, `/profile` и ответ на город текстом не пишут в `users`, включая `last_seen_at`; пишет в `users` только `/start` (как раньше). Это уточняет правило P2 раздела 5 контракта Phase 8 (там `last_seen_at` обновляет любая актуальная кнопка) для кнопок профиля — иначе нарушается PRF-06.
- **Б.** Главное меню после «Пропустить», «Готово» и «⬅️ Назад» из профиля получает `<N>` чтением `users.filters_v` без записи (как кнопка `m`); значение фильтров профиль не читает и не пишет.
- **В.** «✓ » у сохранённого значения — в обоих режимах; «⬅️ Назад» с вопроса 4 ведёт на экран страны вопроса 3; режим `w` показывается только при статусе `in_progress`, иначе устаревшая навигационная кнопка открывает экран поля в режиме `e`.
- **Г.** Уведомление на кнопки профиля пустое, кроме «Спасибо! Анкета сохранена» (O-6) и «Кнопка устарела — нажмите /start»; сохранение ответа текста не показывает.
- **Д.** Текст города приводится к одной строке так же, как поисковый запрос (пробелы и переводы строк — один пробел); проверка длины 64 символа и префикса `/` — после приведения.
