## Phase Boundary

Добровольная анкета из четырёх вопросов (пол, возрастная группа, место проживания, виды спорта), предлагаемая один раз на `/start`, и профиль `/profile` с просмотром и редактированием каждого ответа.

<decisions>
## Implementation Decisions

### Добровольность
- **D-01:** Анкета добровольная: можно пропустить всю анкету и любой вопрос; любой ответ можно позже изменить через `/profile`; отказ не ограничивает поиск и остальные функции.
- **D-02:** Пользовательского удаления профиля нет: ни `/delete_profile`, ни кнопки, ни подтверждения, ни очистки всех ответов. Это не относится к техническому удалению строки `users` и к сбросу настроек поиска — они не меняются.
- **D-03:** Кнопки «Не указывать» у поля нет: ответ либо выбран, либо поле пустое с момента пропуска. Пол, возраст и страну после выбора можно только заменить; у видов спорта можно снять все отметки.

### Содержание анкеты
- **D-04:** Четыре вопроса по порядку:
  1. Пол: «Мужской» / «Женский», коды `m` / `f`.
  2. Возраст: До 18, 18–24, 25–34, 35–44, 45–54, 55+ (коды `0..5`).
  3. Где живёте: страна (Россия, Беларусь, Казахстан, «Другая страна» — код `ZZ`), затем город — кнопками из каталога этой страны или текстом; для «Другой страны» — только текстом.
  4. Виды спорта, можно несколько: 🏃 Бег `run`, 🏔 Трейлраннинг `trail`, 🧗 OCR · гонки с препятствиями `ocr`, 🚴 Велоспорт `bike`, 🏊 Плавание `swim`, ⛷ Лыжные гонки `ski`, 🏅 Триатлон `tri`, 🚣 Гребля `row`. Пункта «Другое» нет.

### Предложение анкеты
- **D-05:** Анкета предлагается один раз: на первом `/start` нового пользователя и на следующем `/start` действующего пользователя (у которого нет строки профиля). Экран предложения приходит вместо главного меню; «Пропустить» открывает главное меню правкой сообщения.
- **D-06:** «Предложена» = создана строка профиля; она создаётся в транзакции `/start` до отправки экрана. Сорвавшаяся отправка повторного предложения не вызывает.

### Данные
- **D-07:** Отдельная таблица `user_profiles` (связь 1:1 с `users`, `ON DELETE CASCADE`), таблица `users` не меняется. Виды спорта — `TEXT[]` с `CHECK` на коды D-04, без таблицы `user_sports`. Схема окончательно фиксируется планом 09-02:

  ```
  tg_id                  BIGINT PK → users(tg_id) ON DELETE CASCADE
  status                 not_started | in_progress | completed | skipped
  gender                 NULL | m | f
  age_group              NULL | 0..5
  residence_country_code NULL | ISO alpha-2 (ZZ — другая страна)
  residence_city         NULL | текст ≤ 64 символов
  residence_city_key     NULL | ключ, если город найден в справочнике
  sports                 TEXT[] DEFAULT '{}'
  profile_v              INTEGER — своя версия, не filters_v
  awaiting_city_until    NULL | timestamptz
  offered_at, started_at, completed_at, updated_at
  ```
- **D-08:** Профиль независим от настроек поиска: код профиля не пишет и не читает `users.filters`, код фильтров не читает `user_profiles`; версии раздельные; автоподстановки нет. Код вида спорта `ocr` и тип события `obstacle` — разные справочники, не связываются.
- **D-09:** Город вне справочника хранится текстом (обрезка пробелов, ≤ 64 символов), `residence_city_key = NULL`; экранируется при выводе, не попадает в `callback_data` и в логи.
- **D-10:** Город текстом принимается только при отметке ожидания `awaiting_city_until` (10 минут); её снимают `/start` и любая кнопка `u:`. При действующей отметке `onText` сохраняет текст как город проживания и в поиск не идёт. Известное ограничение: поисковый запрос, отправленный в это окно, сохранится как город; ответ бота это показывает и даёт «Изменить».
- **D-11:** Ответы хранятся бессрочно для обезличенной статистики и попадают в резервные копии базы. Экран предложения об удалении ничего не обещает.

### Документы
- **D-12:** Новые формулировки (вносятся планом 09-01):
  - BOT-08: «О пользователях хранятся Telegram ID, настройки поиска и ответы добровольной анкеты: пол, возрастная группа, страна и город проживания, виды спорта. Username, имя, телефон и другие данные из Telegram не сохраняются.»
  - `MVP.md` §8.5: «Хранятся Telegram ID, настройки поиска и ответы добровольной анкеты (пол, возрастная группа, страна и город проживания, виды спорта). Анкета необязательна: отказ не ограничивает функции бота, любой ответ можно изменить в `/profile`. Ответы используются только для обезличенной статистики и не показываются другим пользователям. Username, имена и другие данные из Telegram не сохраняются.»
  - `MVP.md` §12.2, первое предложение: «Хранятся Telegram ID, настройки поиска и ответы добровольной анкеты; ответы хранятся бессрочно для обезличенной статистики и попадают в резервные копии базы.»
  - Пункт Out of Scope «Сбор данных участников» остаётся: он про участников забегов из источников.

### Интерфейс
- **D-13:** В главном меню третья кнопка «👤 Мой профиль» (`u:o`).
- **D-14:** Кнопки профиля — новый префикс `u:`; изменяющие несут версию профиля `v<P>` последним полем; режим `w` (анкета) или `e` (редактирование):

  | Кнопка | Формат | Пишет |
  |---|---|---|
  | профиль | `u:o` | нет |
  | начать анкету | `u:b:v<P>` | статус |
  | пропустить анкету | `u:n:v<P>` | статус |
  | показать вопрос | `u:a:<g\|a\|k\|c\|s>:<w\|e>:v<P>` | нет |
  | сохранить ответ | `u:s:<поле>:<значение>:<w\|e>:v<P>` | да |
  | готово | `u:z:v<P>` | статус |

  Ключ города в кнопке — не длиннее 49 байт; более длинный вводится текстом.
- **D-15:** Устаревшая кнопка `u:` (чужая `v<P>` или нет строки профиля): изменяющая — «Кнопка устарела — нажмите /start» без записи; навигационная — экран по текущему состоянию без записи. Правила раздела 5 контракта Phase 8 сохраняются.
- **D-16:** Контракт экранов фазы — отдельный файл `09-UX-CONTRACT.md`; `08-UX-CONTRACT.md` не правится. `TestContractCoverage` расширяется на второй файл.

</decisions>

## Состояния анкеты

```
(нет строки) ──первый /start──▶ not_started
not_started ──«Заполнить анкету»──▶ in_progress
not_started ──«Пропустить»──▶ skipped
in_progress ──«Готово» на 4-м вопросе──▶ completed
not_started / skipped ──первый ответ через /profile──▶ in_progress
in_progress ──все 4 поля заполнены через /profile──▶ completed
completed ──изменение ответа──▶ completed (растут profile_v, updated_at)
```

- Повторный `/start` при любом статусе — главное меню.
- Прерывание (`/start`, текст, молчание) оставляет `in_progress`; сохранённые ответы на месте.
- «Пропустить вопрос» и «Назад» — навигация без записи.
- Обратных переходов из `completed` нет; `skipped` возникает только из предложения.

</states>

## Предлагаемые требования (вносятся в REQUIREMENTS.md планом 09-01)

| ID | Требование | Критерий приёмки |
|---|---|---|
| PRF-01 | Анкета предлагается один раз на `/start` | Второй `/start` при любом статусе — главное меню; одна строка профиля на пользователя |
| PRF-02 | Можно пропустить всю анкету и любой вопрос | «Пропустить» — меню и `skipped`; «Пропустить вопрос» не пишет в БД |
| PRF-03 | Отказ ничего не ограничивает | При `skipped`, `not_started`, `in_progress` сценарии S-01…S-17 проходят; отличия — только экран первого `/start` и кнопка профиля в меню |
| PRF-04 | Пол `m` / `f`, шесть возрастных групп, восемь видов спорта | Экраны и хранимые значения соответствуют D-04; иное значение кодек отвергает |
| PRF-05 | Любой ответ можно изменить через `/profile` | Для каждого из четырёх полей изменение сохраняется, растёт `profile_v` |
| PRF-06 | Профиль независим от настроек поиска | Действия с профилем не меняют строку `users`; действия с фильтрами не меняют строку `user_profiles` |
| PRF-07 | Устаревшие кнопки `u:` не меняют данные | Изменяющая — уведомление без записи; навигационная — экран по текущему состоянию |
| PRF-08 | Город текстом не попадает в поиск | При отметке ожидания текст сохраняется как город проживания, фильтр города не меняется; после её истечения текст идёт в поиск |
| PRF-09 | Ответы не попадают в логи и свободным текстом в `callback_data` | Проверка логов в тестах |
| PRF-10 | Контракт и эталоны утверждены владельцем до кода | Отметка в документах фазы |

</requirements>
