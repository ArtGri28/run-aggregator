## Черновики для контракта

Это предложения исполнителю; окончательный текст — в контракте после сверки с фикстурами и ответа владельца.

**Главное меню (E-01, изменён).** Текст прежний (Q-1). Клавиатура:

```
[🏃 Бег] → f:a:running:v<N> | [⛷ Лыжи] → f:a:skiing:v<N>
[⚙️ Мои настройки] → s:o:v<N>
[👤 Мой профиль] → u:o
[💬 Поддержка] → h:o
```

Строка поддержки — только при включённой поддержке, как сейчас. Подпись кнопки — значок и название из справочника `event.Sports`. Нет будущих лыжных событий — в первом ряду одна кнопка `[🏃 Бег] → f:a:running:v<N>`. Три и более вида — по две кнопки в ряд (D-05).

**Callback вида спорта.** Новая буква семейства `f:` — `a`: `f:a:<код вида спорта>:v<N>`; код — только из справочника. Нажатие запоминает выбранный вид спорта и открывает его сводку. Кнопка `f:s:v<N>` из сообщений, отправленных до выката, остаётся рабочей: открывает сводку выбранного вида спорта (у прежних пользователей — бега).

**Хранение (D-06).** Выбранный вид спорта — ключ `sport` в `users.filters`; ключа нет — бег. Страна, город и период — прежние ключи, общие. Дистанция и тип бега — прежние ключи `dist2` и `type`. Дистанция и дисциплина остальных видов спорта — под отдельными ключами по коду вида спорта. JSON пользователя, не открывавшего лыжи, побайтно прежний.

## Черновик текста миграции

Имя файла — `migrations/00009_event_type_format.sql`.

```sql
-- +goose Up
-- Дисциплина события хранится в event_type; у каждого вида спорта свои
-- значения. Допустимые значения — в справочнике кода; здесь проверяется
-- только формат, как у events.sport.
ALTER TABLE events DROP CONSTRAINT events_event_type_check;
ALTER TABLE events ADD CONSTRAINT events_event_type_check
    CHECK (event_type ~ '^[a-z][a-z_]{1,31}$');

-- +goose Down
-- Прежний закрытый список. NOT VALID: строки с дисциплинами других видов
-- спорта остаются на месте, проверяются только новые и изменяемые строки.
ALTER TABLE events DROP CONSTRAINT events_event_type_check;
ALTER TABLE events ADD CONSTRAINT events_event_type_check
    CHECK (event_type IN ('road', 'trail', 'cross', 'track', 'obstacle', 'other')) NOT VALID;
```

Существующие строки не переписываются: шесть прежних значений формату соответствуют. Прежний образ с новой схемой работает: он пишет только прежние значения.
